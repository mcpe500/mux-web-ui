# Mux Web UI — implementation plan

Status: proposed  
Target pertama: Termux/Android ARM64; Linux x86_64 dan ARM64 sebagai target kedua  
Prinsip utama: web asli, satu binary, ringan, aman secara default

Rencana ini wajib dikerjakan dengan test-driven development mengikuti
[`000a.plan-test.md`](./000a.plan-test.md). Sebuah milestone belum selesai hanya
karena UI terlihat bekerja; seluruh acceptance test terkait harus lebih dahulu lulus.

## 1. Tujuan

Membuat web desktop/control center yang terasa seperti desktop/OS kecil untuk
environment Termux. Pengguna membuka satu URL lokal, melihat desktop, app launcher,
taskbar, notification area, dan banyak window. Aplikasi inti adalah Terminal, File
Explorer, lightweight text editor, System Monitor, dan Settings. Terminal
menjalankan shell nyata pada host melalui PTY (pseudo-terminal), bukan terminal
palsu di browser.

Produk dijalankan sebagai server lokal dan memakai browser yang sudah terpasang.
Browser, shell, dan program yang dijalankan pengguna tidak termasuk ukuran paket
aplikasi.

Use case utama v1 adalah pengguna menjalankan executable dari Termux, misalnya
`mux-web`, lalu membuka URL lokal di browser Android. UI yang muncul menyerupai
desktop kecil, tetapi seluruh shell dan command tetap berjalan di environment
Termux milik pengguna.

### Sasaran terukur

- Paket rilis Linux terkompresi: target <= 10 MiB, batas keras <= 50 MiB.
- Aset frontend terkompresi (Brotli/gzip): target <= 750 KiB.
- RSS server saat idle, tanpa menghitung browser dan proses shell: target <= 35 MiB,
  batas keras <= 50 MiB.
- Waktu mulai server pada perangkat low-end: target <= 1 detik.
- UI tetap responsif dengan 4 terminal aktif pada perangkat 2 core dan RAM 1 GiB.
- Tidak membutuhkan Node.js, npm, atau runtime tambahan pada mesin produksi.
- Artifact utama tersedia untuk Android/Termux `aarch64`; `arm` dan `x86_64`
  ditambahkan hanya bila dapat diuji.

Target <= 10 MiB adalah target optimasi dan harus dibuktikan oleh build CI. Target
ini bukan janji untuk semua OS/arsitektur karena ukuran libc, debug symbol, dan
format executable berbeda.

## 2. Keputusan stack

### Pilihan: Rust + Axum/Tokio + xterm.js + TypeScript/Preact

| Bagian | Teknologi | Alasan |
|---|---|---|
| Backend | Rust stable | Binary native kecil, penggunaan memori terkontrol, aman untuk konkurensi dan I/O |
| HTTP/WebSocket | Axum + Tokio, feature minimal | Ekosistem matang dan cukup sederhana untuk stream terminal |
| PTY | `portable-pty` untuk awal | API lintas platform; dapat diganti implementasi Unix yang lebih kecil bila budget binary gagal |
| Frontend | TypeScript + Preact | State beberapa window lebih mudah dirawat; overhead framework kecil |
| Terminal renderer | `@xterm/xterm` | Emulator terminal browser yang matang; jangan menulis parser ANSI sendiri |
| File dan tools API | Rust standard filesystem/process API | Operasi langsung di environment Termux tanpa service tambahan |
| Build frontend | Vite/esbuild | Hanya build-time; output static di-embed ke binary Rust |
| Styling/layout | CSS native | Tidak memakai UI kit atau utility framework besar |
| Persistence UI | `localStorage` | Layout/theme tersimpan tanpa database dan tanpa beban backend |

Dependency harus dikunci dengan `Cargo.lock` dan lockfile package manager. Matikan
default features yang tidak dipakai. Aset frontend di-minify dan dikompresi pada
build release.

### Mengapa bukan Go atau Zig?

| Opsi | Kelebihan | Kekurangan untuk proyek ini | Putusan |
|---|---|---|---|
| Go | Paling cepat dibuat, standard library bagus, cross-compile mudah | Binary dan idle memory umumnya lebih sulit ditekan untuk target agresif <= 10 MiB | Pilihan kedua bila kecepatan pengembangan lebih penting dari ukuran |
| Rust | Binary dapat di-strip/LTO, memory footprint bagus, ekosistem async dan PTY matang | Compile lebih lambat dan implementasi lebih kompleks | **Pilihan terbaik untuk constraint saat ini** |
| Zig | Binary kecil dan kontrol sangat tinggi | Ekosistem server WebSocket, PTY, dan library production lebih muda; lebih banyak kode custom dan risiko maintenance | Tidak dipilih untuk v1 |

Jika batas sebenarnya hanya <= 50 MiB, Go juga sangat layak. Karena proyek meminta
kemungkinan <= 10 MiB, Rust dipilih. Optimasi ukuran baru dilakukan setelah fitur
minimum berjalan dan hasil benchmark tersedia.

## 3. Batas produk

### MVP

- Halaman desktop penuh dengan wallpaper CSS sederhana, app launcher, taskbar, dan
  notification/status area.
- App registry internal agar Terminal, File Explorer, Editor, System Monitor, dan
  Settings memakai lifecycle window yang sama.
- Banyak window terminal dengan focus/z-index, drag, resize, minimize, maximize,
  restore, dan close.
- Terminal mendukung input, output, resize PTY, copy/paste, scrollback terbatas,
  judul, dan status disconnected/exited.
- File Explorer mendukung breadcrumb, list/grid sederhana, sort, search nama pada
  folder aktif, create folder/file, rename, copy, move, upload, download, trash, dan
  properties.
- File dapat dibuka dengan double-click/tap; folder masuk ke explorer, file teks kecil
  masuk ke editor, dan file lain ditawarkan untuk download/open browser.
- Editor ringan mendukung plain text, dirty-state, save, save-as, line/column, serta
  konfirmasi sebelum menutup perubahan. Syntax highlighting bukan syarat v1.
- System Monitor menampilkan info yang tersedia bagi proses Termux: uptime server,
  CPU/memory server, disk pada allowed root, terminal aktif, dan child process yang
  dibuat aplikasi.
- Quick Actions menyediakan New Terminal, Open Folder, Edit File, Refresh, Stop All
  Terminals, serta command palette yang dapat dicari.
- Layout, theme, dan preferensi disimpan di browser.
- Reconnect transport tidak otomatis menghidupkan proses yang sudah mati.
- Endpoint health dan informasi versi.
- Satu binary rilis yang berisi frontend.

### Bukan MVP

- Bukan kernel, virtual machine, container manager, atau OS baru.
- Tidak ada Electron, browser engine, desktop wrapper, database, plugin system,
  login multi-user, session sharing, atau remote internet.
- Package Manager GUI penuh, Git GUI, archive manager, media viewer, service manager,
  dan integrasi Termux:API bukan bagian v1. Quick Action boleh membuka terminal
  dengan command yang terlihat dan masih harus dikonfirmasi pengguna.
- LAN access dari perangkat lain adalah bagian v1, tetapi internet exposure, port
  forwarding, public hosting, dan multi-user tetap bukan bagian v1.
- Tidak menjanjikan pemulihan terminal setelah server restart.
- Windows dan macOS ditunda sampai versi Termux dan Linux stabil.
- Tidak mengemulasi Android launcher dan tidak memberi akses khusus ke aplikasi atau
  API Android. Integrasi Android kelak harus melalui Termux:API dan bersifat opsional.

## 4. Pengalaman pengguna di Termux

Alur normal harus sesingkat berikut:

```sh
$ mux-web
Mux Web UI: http://127.0.0.1:7681/<bootstrap-secret>
Press Ctrl+C to stop.
```

Untuk mengakses dari laptop pada network yang sama:

```sh
$ mux-web --lan
Local:   http://127.0.0.1:7681
LAN:     http://192.168.1.23:7681
Pairing: ABCD-EFGH (expires in 5 minutes)
Warning: plain HTTP; use only on a trusted LAN.
```

`0.0.0.0` hanya alamat bind, bukan URL yang dibuka pengguna. Server mendeteksi dan
menampilkan IP LAN yang dapat dipakai. Jika ada beberapa interface, tampilkan semua
alamat private yang valid dan abaikan loopback/link-local yang tidak berguna.

- Server memilih port tetap yang dapat diubah dengan flag. Bila port terpakai, gagal
  dengan pesan jelas; jangan diam-diam memakai URL berbeda yang sulit ditemukan.
- Default tetap local-only. `--lan` adalah shortcut eksplisit untuk bind ke
  `0.0.0.0`; `--bind <address>` tersedia untuk pengguna lanjut.
- `--tls-cert <path> --tls-key <path>` mengaktifkan HTTPS/WSS. Sertifikat otomatis
  yang dipercaya lintas Android/laptop ditunda karena distribusi trust root tidak
  sederhana; self-signed certificate boleh didukung dengan warning.
- Bila `termux-open-url` tersedia, flag `--open` membuka browser secara otomatis.
  Fitur ini hanya convenience; instalasi Termux:API bukan dependency wajib.
- Tanpa `--open`, URL dicetak dan dapat ditekan/disalin dari Termux.
- `Ctrl+C` menghentikan server dan semua PTY secara bersih.
- Default working directory adalah current directory saat `mux-web` dijalankan.
- File Explorer dimulai dari home Termux. Allowed roots default adalah home Termux
  dan current directory; root tambahan harus diberikan eksplisit melalui config.
- Default shell dipilih berurutan dari konfigurasi eksplisit, environment `SHELL`
  yang valid, lalu executable `bash`/`sh` dari prefix Termux. Jangan hard-code
  `/bin/bash`, karena path Termux berbeda dari distribusi Linux biasa.
- Jangan meminta root. Semua terminal memiliki permission yang sama dengan aplikasi
  Termux dan tidak boleh mencoba melewati sandbox Android.
- Executable, konfigurasi, dan data internal harus berada di private storage Termux,
  bukan `~/storage`/shared storage yang dapat memiliki batas `noexec` dan filesystem.
  File Explorer hanya boleh masuk ke shared storage bila pengguna menambahkannya
  sebagai allowed root setelah menjalankan `termux-setup-storage` sendiri.

### Adaptasi layar

- Lebar >= 768 px: desktop mode dengan free-form window, taskbar, drag, dan resize.
- Lebar < 768 px: satu aplikasi aktif memenuhi layar; aplikasi lain muncul sebagai
  tab/task switcher. Drag/resize bebas dimatikan agar keyboard Android tetap nyaman.
- Gunakan `100dvh`, safe-area inset, Pointer Events, dan resize dari
  `visualViewport` agar virtual keyboard tidak menutupi prompt.
- Target sentuh minimum 44x44 CSS px dan tidak bergantung pada hover/right-click.
- Saat orientation berubah, debounce pengukuran lalu kirim ukuran cols/rows baru ke
  PTY.

## 5. Arsitektur

```text
Browser yang sudah ada
  Desktop/window manager (Preact + CSS)
    App registry + shared window lifecycle
      TerminalView (xterm.js) ---- WebSocket biner per session
      File Explorer/Editor ------- HTTP file API
      System Monitor ------------- HTTP metrics API
        Rust HTTP server
          Auth + allowed-root policy
          Terminal session registry -> PTY master <-> shell child
          Filesystem service
          Metrics/process service
```

Backend hanya bind ke `127.0.0.1` secara default. Static HTML/CSS/JS dikompilasi
lebih dahulu, lalu di-embed ke executable. Satu session terminal memiliki tepat
satu PTY, proses child, reader task, writer path, dan lifecycle state.

Pada `--lan`, server listen pada seluruh interface tetapi akses tetap ditutup sampai
browser menyelesaikan pairing. Laptop tidak menjalankan shell sendiri: input keyboard
dikirim ke PTY di HP, dan output program interaktif seperti `nano`, `vim`, `top`, atau
`htop` dirender oleh xterm.js di browser laptop.

Frontend apps bukan iframe dan bukan process terpisah. Semuanya component yang
di-lazy-load oleh app registry, tetapi setiap instance mempunyai window id, app id,
title, icon, bounds, state, dan lifecycle hooks sendiri. Backend dipisah menjadi
service kecil agar File Explorer tidak dapat memanggil primitive PTY/process secara
langsung.

Build Termux bukan binary Linux glibc/musl biasa: target Android harus kompatibel
dengan Bionic dan layout environment Termux. CI menghasilkan artifact
`aarch64-linux-android`, lalu smoke test wajib dijalankan pada Termux nyata atau
emulator Android yang representatif. Jangan menganggap artifact Linux ARM64 dapat
langsung dijalankan di Termux.

Gunakan satu WebSocket per terminal pada MVP. Ini sedikit menambah koneksi tetapi
membuat backpressure, cleanup, dan isolasi kegagalan jauh lebih sederhana. Jangan
mengirim output terminal lewat JSON; gunakan frame biner agar hemat CPU dan ukuran.

## 6. Kontrak API dan protokol

### HTTP

- `GET /` dan aset: UI embedded, dengan cache immutable untuk aset ber-hash.
- `GET /api/v1/health`: status server dan versi protokol.
- `POST /api/v1/auth/pair`: tukarkan pairing code sekali pakai dengan session cookie;
  endpoint memiliki expiry, attempt limit, dan rate limit per IP/global.
- `POST /api/v1/auth/logout`: revoke session dan tutup seluruh WebSocket miliknya.
- `GET /api/v1/auth/clients`: daftar client aktif tanpa secret untuk UI Settings.
- `DELETE /api/v1/auth/clients/{id}`: revoke client dari HP/control center.
- `POST /api/v1/terminals`: membuat PTY; menerima `cols` dan `rows`; mengembalikan
  `id`, token session sekali pakai, dan metadata.
- `DELETE /api/v1/terminals/{id}`: terminasi session secara idempotent.
- `GET /api/v1/terminals/{id}/ws?token=...`: upgrade WebSocket.
- `GET /api/v1/fs/roots`: allowed roots sebagai opaque root id, bukan path bebas.
- `GET /api/v1/fs/entries?root={id}&path={relative}`: metadata isi direktori.
- `GET /api/v1/fs/file?root={id}&path={relative}`: stream download dengan range dan
  content type aman.
- `PUT /api/v1/fs/file?root={id}&path={relative}`: upload/save dengan batas ukuran,
  temporary file, fsync bila tersedia, lalu atomic rename.
- `POST /api/v1/fs/actions`: create-dir, create-file, rename, copy, move, dan trash
  menggunakan schema bertipe; bukan menerima command shell.
- `GET /api/v1/metrics`: metrics yang tersedia dan daftar session/child process milik
  aplikasi.
- `POST /api/v1/actions/terminals/stop-all`: menghentikan semua session setelah
  konfirmasi di UI.

Jangan menerima command arbitrary dari request pada MVP. Request `Open Terminal Here`
boleh membawa opaque root id dan relative path yang dicanonicalize di backend. Shell
berasal dari konfigurasi server lokal yang tervalidasi.

### Aturan filesystem

- Browser tidak pernah mengirim absolute path sebagai authority. Semua operasi memakai
  pasangan `root_id + relative_path`.
- Decode path sekali, tolak NUL, `..`, dan path absolute; canonicalize target/parent
  lalu pastikan tetap berada di allowed root.
- Symlink ditampilkan sebagai symlink. Jangan mengikuti symlink keluar allowed root
  kecuali destination juga merupakan allowed root eksplisit.
- Jangan memuat file besar ke RAM. List directory dipaginasi dan upload/download/copy
  menggunakan streaming dengan batas konkurensi.
- Save editor memakai optimistic concurrency (`etag`/mtime + size). Bila file berubah
  di luar editor, tampilkan conflict; jangan menimpa diam-diam.
- Trash lebih diutamakan daripada permanent delete. Permanent delete membutuhkan
  dialog kedua yang menyebut nama target dan tidak boleh bekerja rekursif tanpa flag
  eksplisit dari action schema.
- Jangan mengekstrak archive pada v1; ini menghindari path traversal dan zip bomb.

### Frame WebSocket

Byte pertama adalah tipe frame, sisanya payload:

- `0x00 OUTPUT`: server -> client, raw bytes dari PTY.
- `0x01 INPUT`: client -> server, raw bytes keyboard/paste.
- `0x02 RESIZE`: client -> server, dua unsigned 16-bit big-endian: cols, rows.
- `0x03 EXIT`: server -> client, signed 32-bit exit code.
- `0x04 ERROR`: dua arah, pesan UTF-8 pendek dan aman ditampilkan.
- `0x05 PING` / `0x06 PONG`: deteksi koneksi mati bila ping WebSocket bawaan
  tidak mencukupi implementasi browser.

Batasi ukuran setiap frame, panjang paste, ukuran antrean output, jumlah session,
dan nilai resize. Versi protokol dinaikkan bila layout frame berubah.

## 7. Lifecycle terminal

State session: `creating -> running -> exiting -> closed`, dengan transisi
`creating/running -> failed`. Session registry memegang owner handle dan melakukan
cleanup tepat sekali.

- Close window meminta `DELETE`, menutup PTY, lalu mengirim TERM ke process group.
- Setelah grace period pendek, gunakan KILL hanya untuk process group milik session.
- WebSocket terputus tidak langsung membunuh shell; beri reconnect grace period yang
  terbatas agar refresh singkat tidak menghilangkan pekerjaan.
- Setelah grace period habis, terminasi session untuk mencegah proses yatim.
- Server shutdown berhenti menerima session, menutup semua PTY, menunggu grace
  period, lalu keluar.
- Output memakai bounded channel. Client lambat tidak boleh membuat RAM tumbuh tanpa
  batas; putuskan client/session dengan error yang jelas saat limit terlampaui.
- Kehilangan proses akibat lifecycle/battery policy Android harus tampil sebagai
  disconnected, bukan membuat browser menggantung. UI menyediakan tombol reconnect
  server dan penjelasan singkat bahwa proses lama mungkin sudah dihentikan Android.

## 8. Keamanan minimum

Terminal web pada dasarnya memberi kemampuan menjalankan perintah sebagai user yang
menjalankan server. Karena itu keamanan adalah acceptance criterion, bukan fitur
tambahan.

- Default listen hanya `127.0.0.1`; bind non-loopback hanya melalui `--lan` atau
  `--bind` eksplisit dan selalu menampilkan warning bila TLS mati.
- Local mode mencetak bootstrap secret acak. LAN mode mencetak pairing code acak,
  single-use, berumur 5 menit, dengan maksimum percobaan ketat. Regenerate/revoke
  dapat dilakukan dari terminal host atau Settings.
- Tukarkan bootstrap/pairing credential menjadi cookie `HttpOnly`, `SameSite=Strict`,
  dan `Secure` ketika TLS aktif; jangan simpan credential di `localStorage` atau URL
  setelah pairing selesai.
- Semua state-changing HTTP request memakai CSRF token. Validasi exact `Origin` dan
  `Host` allowlist pada HTTP maupun WebSocket upgrade; jangan memakai wildcard atau
  substring matching.
- Token WebSocket bersifat acak, single-use, session-scoped, dan berumur pendek.
- Session terikat ke client record, memiliki idle/absolute expiry, dapat direvoke, dan
  revocation langsung menutup seluruh WebSocket client tersebut.
- Terapkan limit session, koneksi, frame, paste, resize, dan request body.
- Server menolak berjalan sebagai root secara default; override harus eksplisit dan
  memberi warning besar.
- Tidak ada interpolasi shell untuk konfigurasi command. Spawn executable dan args
  secara langsung.
- Semua filesystem endpoint menerapkan allowed-root policy setelah canonicalization,
  termasuk source dan destination operasi move/copy.
- Response file memakai `Content-Disposition` dan `X-Content-Type-Options: nosniff`;
  file HTML/SVG pengguna tidak boleh dieksekusi sebagai origin aplikasi.
- Log tidak boleh memuat token, cookie, input terminal, atau output terminal.
- LAN dianggap hostile: device lain dapat mencoba pairing, flooding, atau sniffing.
  Plain HTTP hanya untuk trusted LAN dan tidak melindungi input/output terminal dari
  penyadapan. Untuk network yang tidak sepenuhnya dipercaya, wajib HTTPS/WSS.
- Jangan membuka aplikasi langsung ke internet. Remote internet kelak wajib memakai
  TLS, autentikasi kuat/VPN, dan threat model terpisah.
- Plain HTTP melalui IP LAN bukan secure context browser; fitur Clipboard API dan API
  web tertentu harus degrade gracefully ke selection/copy/paste native atau memberi
  instruksi memakai HTTPS.

## 9. Rencana pengerjaan

### Milestone 0 — baseline dan budget

- Inisialisasi workspace Rust dan frontend TypeScript.
- Tambahkan build release reproducible dan embed halaman statis minimal.
- CI mencatat ukuran binary raw/stripped/compressed dan RSS idle.
- Buat halaman kosong yang dapat diakses hanya dari loopback.
- Hasilkan artifact Android `aarch64-linux-android` dan Linux terpisah.

Selesai jika satu binary dapat menjalankan halaman embedded dan laporan size/RSS
tersimpan sebagai artifact CI.

### Milestone 1 — vertical slice satu terminal

- Spawn satu shell melalui PTY dengan ukuran awal tervalidasi.
- Hubungkan input/output/resize lewat protokol WebSocket biner.
- Render dengan xterm.js dan fit addon yang di-load hanya saat dibutuhkan.
- Tangani exit, close, disconnect, dan shutdown tanpa child process yatim.

Selesai jika shell interaktif mendukung `nano`, `vim`, `top`/`htop`, alternate screen,
mouse mode terminal, resize, Ctrl+C, dan Unicode dasar, serta test memastikan child
dibersihkan.

### Milestone 2 — desktop, app launcher, dan multi-window

- Implementasikan store window, focus dan z-index.
- Tambahkan drag/resize dengan Pointer Events, serta minimize/maximize/restore.
- Tambahkan app registry, launcher, taskbar, status session, command palette, dan
  keyboard shortcut.
- Suspend rendering terminal yang diminimalkan bila aman; jangan hilangkan PTY.
- Simpan hanya metadata layout/preference ke `localStorage`, bukan output terminal.
- Implementasikan desktop mode untuk tablet dan tab/fullscreen mode untuk HP,
  termasuk perubahan ukuran akibat virtual keyboard dan orientation.

Selesai jika empat terminal dapat dipakai independen, placeholder semua core app
dapat dibuka, dan seluruh operasi window dapat dilakukan dengan mouse, touch dasar,
dan keyboard.

### Milestone 3 — File Explorer dan Editor

- Implementasikan allowed-root resolver dan seluruh aturan filesystem.
- Tambahkan list/breadcrumb/search, create, rename, streaming copy/move,
  upload/download, trash, dan properties.
- Tambahkan editor plain text dengan atomic save, dirty-state, conflict detection,
  batas ukuran file, serta `Open Terminal Here`.
- Uji symlink escape, traversal encoded, overwrite race, file besar, storage penuh,
  permission denied, dan disconnect ketika upload/save.

Selesai jika pengguna dapat mengelola project Termux dari UI tanpa memakai command
untuk operasi file harian, dan seluruh path tetap berada dalam allowed roots.

### Milestone 4 — Control Center dan hardening

- Tambahkan System Monitor, Settings, Quick Actions, dan stop-all terminals.
- Metrics hanya mengekspos proses milik aplikasi atau data system yang memang dapat
  dibaca tanpa root.
- Tambahkan `--lan`, deteksi/display IP private, pairing code single-use, client list,
  logout/revoke, session expiry, CSRF token, serta TLS dari certificate/key pengguna.
- Tampilkan indikator permanen ketika LAN aktif dan jumlah client tersambung. Plain
  HTTP harus menampilkan warning yang tidak menutupi UI terminal.

- Implementasikan bootstrap auth, cookie, Origin/Host check, token session single-use,
  rate/size limits, dan root refusal.
- Tambahkan bounded queues, backpressure, reconnect grace, dan graceful shutdown.
- Uji close race, refresh berulang, client lambat, frame rusak, dan process tree.
- Audit dependency dan pastikan log tidak membocorkan data terminal.

Selesai jika test security/lifecycle lulus dan tidak ada proses yatim pada semua jalur
close dan operasi file yang diuji.

### Milestone 5 — optimasi low-end dan release

- Profil CPU, RSS, startup, throughput, dan ukuran; optimasi berdasarkan data.
- Rust release: `panic=abort`, LTO, satu codegen unit, strip symbols, dan feature
  pruning. Uji `opt-level="z"` versus performa sebelum menetapkannya.
- Lazy-load fitur frontend non-kritis, batasi scrollback, hindari animation loop dan
  shadow/blur mahal, hormati `prefers-reduced-motion`.
- Buat artifact Linux x86_64 dan ARM64 beserta checksum dan SBOM.
- Buat artifact Termux/Android ARM64, checksum, serta petunjuk install/update satu
  executable tanpa toolchain Rust/Node pada perangkat pengguna.
- Dokumentasikan konfigurasi shell, limit resource, dan cara uninstall.

Selesai jika seluruh budget pada bagian 1 lolos pada mesin benchmark yang dicatat.
Jika paket masih >10 MiB tetapi <=50 MiB, rilis boleh diberi status beta dengan hasil
benchmark transparan; jangan mengganti stack sebelum profiler menunjukkan penyebab.

## 10. Strategi test

- Unit: codec frame, validasi ukuran, state machine, config, token expiry.
- Integration: create/connect/input/output/resize/exit/delete dan disconnect race.
- Process cleanup: periksa process group setelah close dan shutdown.
- Browser E2E: create empat window, focus, drag, resize, minimize, restore, close,
  launcher, command palette, file workflow, editor conflict, reload, serta navigasi
  keyboard.
- Filesystem integration: allowed roots, traversal/symlink escape, streaming file
  besar, atomic save, conflict, storage/permission error, trash, dan cross-root move.
- Termux device test: spawn shell Termux, resolve executable dari prefix, open dari
  browser Android, virtual keyboard, orientation change, background/foreground, dan
  server yang dihentikan Android.
- LAN E2E: jalankan di HP, pair dari browser laptop, gunakan `nano`/`vim`, reconnect,
  expiry code, brute-force limit, revoke client, multiple interface, serta network
  disconnect/reconnect.
- Security: invalid Origin/Host/token, replay token, oversized frames, session limit,
  CSRF, pairing brute force, session revoke/expiry, non-loopback default, plain-HTTP
  warning, dan run-as-root refusal.
- Performance: startup median/p95, RSS idle dan empat terminal, CPU saat output deras,
  ukuran raw/stripped/compressed, serta ukuran aset gzip/Brotli.

Benchmark harus mencatat commit, compiler, target, kernel, CPU, dan RAM agar hasil
dapat dibandingkan. Browser memory dilaporkan terpisah dari server memory.

## 11. Definition of done v1

- Semua fungsi MVP wajib lulus pada Termux Android ARM64 dan test backend wajib lulus
  pada Linux x86_64/ARM64.
- Tidak ada child/process group yang tertinggal setelah window atau server ditutup.
- Terminal, File Explorer, Editor, System Monitor, Settings, launcher, taskbar, dan
  command palette bekerja pada desktop dan mobile mode.
- File API tidak dapat membaca/menulis di luar allowed roots pada corpus test path dan
  symlink yang ditentukan.
- Default tidak dapat diakses dari jaringan lain.
- `--lan` dapat diakses dari browser laptop pada network yang sama hanya setelah
  pairing; revoke dari HP segera memutus API dan terminal client.
- Paket tidak membutuhkan runtime produksi selain OS, shell, dan browser yang sudah
  tersedia.
- Batas <=50 MiB wajib; hasil terhadap target <=10 MiB dan budget RSS dipublikasikan.
- Dokumentasi membedakan local, trusted-LAN HTTP, LAN HTTPS, dan internet exposure;
  membuka akses ke internet sama dengan membuka akses shell dan tidak didukung v1.

## 12. Risiko khusus Android/Termux

- Android dapat membatasi atau membunuh child/phantom process, terutama saat aplikasi
  berada di background, perangkat kekurangan RAM, atau battery optimization aktif.
- Wake lock dapat mengurangi sebagian gangguan tetapi meningkatkan konsumsi baterai;
  aplikasi tidak mengaktifkannya otomatis pada MVP. Dokumentasikan sebagai pilihan
  pengguna bila command Termux terkait tersedia.
- Setiap terminal tambahan adalah child process nyata. Default maksimal empat session
  pada Termux low-end dan dapat dikonfigurasi sampai batas aman.
- Browser mobile sendiri mungkin memakai RAM jauh lebih besar daripada server. Klaim
  budget <=50 MiB hanya untuk server; ukur browser secara terpisah pada device test.
- PTY crate dan signal/process-group behavior harus diuji di Bionic. Jika
  `portable-pty` tidak kompatibel atau terlalu besar, buat adapter Unix/Android kecil
  di balik trait internal, bukan menyebarkan conditional code ke seluruh backend.

## 13. Aplikasi lanjutan setelah v1

- Package Center: daftar/search package, update, install, uninstall, dan progress.
  Operasi tetap dijalankan melalui PTY/task yang terlihat, bukan shell command
  tersembunyi.
- Git UI: status, diff, stage, commit, branch, pull/push; credential tidak disimpan
  oleh Mux Web UI.
- Archive Manager dengan extraction sandbox dan limit anti zip-bomb.
- Service/Task Center untuk task yang didefinisikan pengguna, log, start/stop, dan
  autostart melalui mekanisme Termux yang tersedia.
- Image/media preview yang di-lazy-load, tanpa codec native yang memperbesar binary.
- Integrasi Termux:API opsional untuk clipboard, notification, share, battery, dan
  membuka URL/file dengan Android.
- App/plugin SDK hanya setelah permission model dan versioned capability API selesai.

## 14. Keputusan yang sengaja ditunda

- Dukungan Windows/macOS dan pilihan library PTY final per platform.
- Plugin API dan akses remote melalui internet/VPN.
- Session persistence lintas restart, multiplex satu WebSocket, serta kolaborasi.
- Packaging sebagai PWA/Tauri. PWA boleh ditambahkan kelak; Tauri hanya bila benar-
  benar diperlukan karena produk utama tetap server web dan browser eksternal.
