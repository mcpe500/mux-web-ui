## 1. Latar Belakang & Risiko

### 1.1 Skenario User

1. **Coding agent di HP (Termux)**: user menjalankan `opencode` / `claude` /
   `codex` / `antigravity` di dalam distro proot-distro (mis. Ubuntu) dari
   browser laptop/HP. Agent berjalan menit-menitan; layar HP mati atau browser
   di-background → WS putus → **saat ini sesi dibunuh 60 detik kemudian** dan
   pekerjaan agent hilang.
2. **Pilih environment**: user ingin terminal baru langsung masuk ke distro
   proot pilihan (`proot-distro login ubuntu -- bash -l`) tanpa mengetik manual.
3. **Quick-launch agent**: satu klik "OpenCode di Ubuntu @ ~/proyek" → terminal
   ter-spawn dengan environment, cwd, dan binary agent yang benar.
4. **Editor layak pakai**: syntax highlighting, search/replace, go-to-line —
   feel VSCode, tanpa menggembungkan bundle.

### 1.2 Kondisi Saat Ini (fakta kode — titik awal)

| Fakta | Lokasi | Implikasi |
|---|---|---|
| Resolve shell: `--shell` → `$SHELL` → autodetect Termux/Linux; hasilnya **satu path shell**, argv selalu `[shell]` | `src/pty.rs:29-44`, argv `[shell, NULL]` `src/pty.rs:198-202` | Tidak ada mekanisme wrapper command (mis. `proot-distro login …`) |
| `create_terminal_handler` hanya menerima `cwd_root`/`cwd_path`/size → `create_session(cols, rows, work_dir, config.shell)` | `src/http.rs:37` (`CreateTerminalReq`), `:578-606` | Payload belum punya konsep *environment/profile* |
| Janitor reap sesi detached setelah grace: tick 1 s, cek `has_client`, lalu bandingkan `idle_deadline` | `src/session.rs:254-273` | Sesi detached **selalu** mati tepat saat grace habis — meski agent sedang streaming output |
| Detach memasang deadline `now + grace_period`; attach menghapusnya; exit watcher memasang grace bila tanpa client | `src/session.rs:335-345`, `:321-332`, `:245-247` | Titik sisip busy-grace jelas: janitor + detach |
| Config default: `session_idle_timeout` 60 s, `session_output_buffer` 256 KiB, `max_sessions` 4 (clamp 1..=16) | `src/config.rs:56-70`, clamp `:156-161` | Grace 60 s terlalu pendek untuk run agent; buffer replay kecil untuk output agent yang besar |
| Output frame langsung `term.write(payload)` per frame WS | `web/src/apps/terminal/TerminalView.tsx:90` | Banjir output agent → render spike di webview mobile |
| Deps frontend hanya xterm+fit+unicode11+preact; editor plain 1213 baris tanpa highlighting | `web/package.json`, `web/src/apps/editor/TextEditorView.tsx` | Fitur editor jauh di bawah VSCode; tidak ada tokenizer |
| Budget aset ≤750 KiB brotli/gzip; idle RSS ≤35 MiB | `tests/traceability.md` PERF-002/003 (:135-136) | Monaco (~MB) mustahil; engine in-house wajib hemat |

### 1.3 Risiko Tanpa Desain

- **Agent mati mid-run** (penyebab komplain #1): grace 60 s + browser mobile
  yang background = pekerjaan agent lenyap tanpa jejak.
- **Path translation proot**: cwd host (mis. `/data/data/com.termux/files/home/proyek`)
  berbeda dari path di dalam distro (bind mount berbeda). Salah translate →
  agent jalan di folder salah, diam-diam.
- **Budget burst**: engine editor naif bisa menambah ratusan KB dan melanggar
  PERF-002; tokenizer tanpa virtualisasi bisa nge-lag di file besar.
- **Deteksi agent sembarangan** (mis. resolve `$PATH` di proses server, bukan
  di konteks distro) → quick-launch menampilkan agent yang sebenarnya tidak ada.

## 3. Threat Model

### Yang dilindungi

- **Auth tetap gerbang segala endpoint baru** (`environments`, `agents`,
  quick-launch) — tidak ada jalur unauthenticated baru.
- **Eksekusi command terbatas allowlist**: server HANYA pernah mengeksekusi
  (a) wrapper `proot-distro login <distro>` untuk distro hasil list lokal, dan
  (b) binary agent dari registry statis AGT-001. Input user (nama distro/agent)
  divalidasi ketat terhadap daftar hasil deteksi — bukan string bebas →
  anti injection (pola PKG-005/GIT-007).
- **cwd translation fail-closed**: path di luar prefix shared → fallback HOME
  distro, tidak pernah `cd` ke path arbitrer host.
- **Output ring buffer tetap bounded** — busy-grace memperpanjang umur sesi,
  bukan ukuran buffer (memori aman di 1 GiB device, PERF-003).
- Deteksi agent via probe read-only (`command -v`), tanpa menjalankan isi file.

### Yang tidak dilindungi (di luar scope threat model)

- Proses di dalam distro proot adalah shell penuh milik user — sandboxing
  tambahan di dalam distro bukan tujuan spec ini (sama seperti terminal biasa).
- Keamanan jaringan antara browser↔server mengikuti AUTH/LAN/NET existing.

## 4. Milestone A — Environment proot-distro (`PROOT-001..006`)

### Perilaku

1. Startup/runtime: server membaca `~/.proot-distro/installed-distros/`
   (nama file = nama distro) sebagai sumber kebenaran; jika binary
   `proot-distro` tidak ada → daftar env = hanya `termux`.
2. `GET /api/v1/environments` → `[{id:"termux",name:"Termux"},{id:"ubuntu",name:"Ubuntu"},…]`.
3. Create terminal dengan `env_id:"ubuntu"`:
   - argv = `["proot-distro","login","ubuntu","--", <shell ter-resolve>]`
     (shell tetap lewat rantai lama `src/pty.rs:29-44`);
   - cwd: jika host cwd di bawah prefix shared yang dikonfigurasi/dikenali
     → dipakai apa adanya (bind mount proot memetakan path host);
     jika tidak → child `cd $HOME` di dalam distro;
   - label metadata session membawa `env` untuk UI.
4. Tanpa `env_id`: jalur kode lama persis (argv `[shell]`) — regresi nol,
   dikunci test.

### Keputusan desain

- Sumber list distro = filesystem (`installed-distros/`), bukan parse stdout
  CLI → cepat, tanpa fork saat list; CLI hanya fallback bila direktori tak ada.
- Wrapper di level argv builder PTY (bukan script shell gabungan) agar escape
  argumen aman dan testable unit murni.
- Prefix shared default: `$HOME`, `/sdcard`, `/storage/emulated/0` (konsisten
  bind default proot-distro di Termux). Konfigurasi tambahan menyusul bila perlu
  (§7 tidak menambah flag di M-A).

### Acceptance criteria

- Unit: resolver distro benar pada fixture direktori (ada/kosong/tidak ada dir).
- Integration: fake `proot-distro` (script di PATH milik test) — create dengan
  `env_id` menghasilkan argv wrapper persis; tanpa `env_id` argv `[shell]`.
- `env_id:"nope"` → 400 actionable; distro dihapus antara list dan spawn →
  error EXIT frame informatif, tanpa panic/orphan (LIFE-002 tetap hijau).

## 5. Milestone B — Coding Agents (`AGT-001..005`)

### Perilaku

1. Registry statis di server:

   | agent_id | binary | catatan |
   |---|---|---|
   | `opencode` | `opencode` | primer; butuh proot-distro di Termux |
   | `claude-code` | `claude` | Claude Code |
   | `codex` | `codex` | Codex CLI |
   | `antigravity` | `agy` | ⚠️ nama binary diverifikasi saat implementasi (Q1) |

2. `GET /api/v1/environments/:id/agents` → status per agent (found/not) via
   probe konteks-env (AGT-002), cache 30 s per (env,agent).
3. Quick-launch: payload create_terminal `{"env_id":"ubuntu",
   "agent_id":"opencode","cwd_root":…,"cwd_path":…}` → PTY exec
   `<wrapper> sh -lc 'command cd <cwd> && exec opencode'` (argumen agent dari
   registry, bukan input user).
4. UI: tombol Agents di workspace → FolderPicker (reuse EDT-006) → daftar
   agent terdeteksi untuk env aktif → spawn; tab berlabel `[agent@env]`.

### Keputusan desain

- Probe agent mahal (fork proot) → cache TTL 30 s + invalidation manual saat
  user refresh menu; probe paralel per-agent, timeout probe 3 s.
- Exec agent via `sh -lc 'exec …'` agar PID child = proses agent (exit code
  akurat di EXIT frame, LIFE-003 tetap bersih).

### Acceptance criteria

- Unit: mapping registry→argv builder (semua 4 agent × {host,distro}).
- Integration: fake PATH/proot — deteksi found/not benar; quick-launch
  menghasilkan command line persis; guard MAX_SESSIONS 409 tetap (TAB-001).
- Frontend vitest: menu render, disable bila agent not-found, label tab.

## 6. Milestone C — Anti-Timeout & Banter (`SESS-009/010`, `LIFE-010`, `PERF-006`) — PRIORITAS #1 USER

### Perilaku

1. **Busy-grace (SESS-009)**: instance session mencatat `last_output: Instant`
   (diupdate di jalur output PTY→ring buffer). Janitor (`src/session.rs:265-271`)
   sebelum mereap: jika `now - last_output < busy_grace` → geser `idle_deadline`
   maju (extend), jangan rekap. Efek: agent yang masih streaming **tidak pernah
   dibunuh** walau detached; agent diam >grace+busy → rekap normal (tetap ada
   batas memori).
2. **Disable flag (SESS-010)**: `--session-idle-timeout 0` → janitor melewati
   rekap idle sepenuhnya (exit watcher & stop manual tetap bekerja).
3. **Heartbeat (LIFE-010)**: WS ping server tiap 20 s idle; client balas pong +
   reconnect eksponensial (existing reconnect LIFE-004/007 dipertahankan).
4. **Coalescing (PERF-006)**: frame OUTPUT ditampung buffer mikro, flush
   `term.write` maksimum 1×/animation frame (rAF), plus yield bila backlog >
   ambang agar input tetap enteng (insertion point `TerminalView.tsx:90`).

### Keputusan desain

- Default perilaku AMAN: `session_idle_timeout` tetap 60 s, `busy_grace`
  default 30 s — sesi zombie murni tetap tereap; hanya sesi beraktivitas yang
  dihidupkan. (Kombinasi disetujui developer.)
- `last_output` diupdate di task reader PTY (single writer) → Mutex<Instant>
  murah, tanpa perubahan protokol wire.
- Heartbeat di frame kontrol protokol existing (bukan opcode WS raw) agar
  share/read-only ikut gratis bila perlu — final di implementasi (D-log).

### Acceptance criteria

- Integration Red: sesi detached dengan output periodik <busy_grace interval
  **tidak direap** melewati grace lama (≥2× grace); sesi detached sunyi →
  direap tepat sesuai perilaku lama (regresi terkunci).
- Unit/integration: `idle_timeout=0` → tidak ada rekap idle sama sekali.
- Coalescing: vitest batching logic (frame ganda dalam 1 tick → 1 write);
  manual smoke: `yes | cmatrix`-grade flood tetap bisa mengetik.
- Regresi: SESS-001..008, LIFE-001..009 hijau tanpa edit.

## 7. Milestone D — Editor Engine In-house "mux-code" (`EDIT-009..016`, `PERF-007`)

### Perilaku

Engine teks editor in-house (tanpa dependensi eksternal), arsitektur ala
Monaco yang dipangkas untuk mobile webview:

1. **Model**: array garis + piece-tree ringan; mutasi O(edit) kecil.
2. **Tokenizer table-driven** (EDIT-009): aturan keyword/comment/string/number/
   function per bahasa (JS/TS/PY/RUST/JSON/MD/SHELL; fallback plain) — state
   minimal per baris, inkremental per-baris saat edit.
3. **Virtualized viewport** (EDIT-010): render hanya baris visible ±overscan;
   gutter nomor baris; scroll tanpa jank pada file besar.
4. **Overlay input** (EDIT-011): textarea transparan menangkap ketikan/IME;
   layer highlight `<pre>` di belakang; selection & caret native.
5. **Fitur**: search/replace + goto-line (EDIT-012), bracket match/auto-close
   (EDIT-013), wrap toggle + font size (EDIT-014), statusbar Ln:Col/EOL/lang
   (EDIT-015).
6. **Lazy chunk** (EDIT-016): dynamic import — desktop bundle awal tidak
   membengkak; total aset tetap lolos gate (PERF-007/PERF-002).

Save/conflict/atomic write memakai jalur existing EDIT-005/006 (tidak diubah).

### Keputusan desain

- Tokenizer = data (tabel rule) + loop kecil, bukan parser penuh — target
  biner frontend tambahan **<60 KiB gzip** seluruh engine.
- Minimap & LSP eksplisit out-of-scope (§9) — biaya/benefit buruk di budget ini.

### Acceptance criteria

- Vitest: tokenizer snapshot per bahasa; model edit (insert/delete/multi-line)
  konsisten; search/replace hit count benar; virtualization hanya render
  viewport (assert jumlah node DOM dibatasi pada file 10k baris).
- Gate: `check_budget.sh` PASS; chunk editor terpisah di output build.
- Manual smoke: buka file 10 MB log → scroll mulus; edit TS/MD/Sh nyaman.
