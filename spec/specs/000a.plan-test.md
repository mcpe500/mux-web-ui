# Mux Web UI — TDD and verification plan

Status: required companion to [`000.plan.md`](./000.plan.md)  
Scope: backend Rust, frontend web, PTY, filesystem, LAN, security, Termux device  
Rule utama: production behavior ditulis melalui failing test terlebih dahulu

## 1. Tujuan

Dokumen ini mengubah implementation plan menjadi proses test-driven development
(TDD) yang dapat diverifikasi. Tujuannya bukan sekadar mengejar angka coverage,
melainkan mencegah regression pada bagian berisiko tinggi: lifecycle process,
terminal interaktif, operasi file, path traversal, authentication, LAN access, dan
perilaku Android/Termux.

Setiap fitur dalam `000.plan.md` harus memiliki:

1. acceptance criterion yang dapat diamati;
2. minimal satu test yang gagal sebelum implementasi;
3. implementasi minimum untuk membuat test lulus;
4. refactor tanpa mengubah behavior;
5. bukti test pada CI atau device test yang relevan.

## 2. Aturan kerja TDD

### Red

- Pilih satu behavior kecil dari milestone aktif.
- Beri test ID dan tulis test pada level terendah yang dapat membuktikannya.
- Jalankan test dan pastikan gagal karena behavior belum ada, bukan karena syntax,
  fixture, dependency, atau environment rusak.
- Simpan pesan kegagalan yang jelas. Test yang langsung hijau tidak membuktikan TDD;
  perbaiki test atau dokumentasikan bahwa behavior memang sudah tersedia.

### Green

- Tulis perubahan production paling kecil yang membuat test tersebut lulus.
- Jalankan test spesifik, lalu seluruh suite cepat yang berkaitan.
- Jangan memperluas public API atau menambahkan abstraction hanya untuk kemungkinan
  fitur masa depan.

### Refactor

- Hilangkan duplication, rapikan nama dan boundary, serta kecilkan dependency.
- Jalankan seluruh suite yang terkena dampak setelah setiap refactor.
- Refactor tidak boleh mengubah snapshot/expected output tanpa alasan yang direview.

### Aturan bug

Setiap bug wajib dimulai dengan regression test yang mereproduksi bug. Test harus
gagal pada revision bermasalah dan lulus setelah fix. Bila bug hanya muncul di device
tertentu, buat reproducer terkecil pada device lalu tambahkan unit/integration test
portable sejauh memungkinkan. Cantumkan device regression test bila tidak dapat
diportable-kan.

### Aturan merge

- Tidak boleh menonaktifkan, skip, `todo`, quarantine, atau memperlonggar assertion
  hanya agar CI hijau tanpa issue dan alasan tertulis.
- Flaky test diperlakukan sebagai bug. Perbaiki determinism; retry hanya boleh menjadi
  alat diagnosis dan bukan hasil pass resmi.
- Perubahan behavior harus mengubah test lebih dahulu atau dalam commit/PR yang sama.
- Review harus dapat memetakan requirement -> test ID -> bukti hasil.
- Generated artifact, secret, token, path home nyata, dan output terminal pengguna
  tidak boleh masuk fixture atau log CI.

## 3. Test ID dan traceability

Gunakan format `AREA-NNN`, misalnya `TERM-012`. Area resmi:

| Area | Scope |
|---|---|
| `BOOT` | startup, config, bind, shutdown, embedded assets |
| `AUTH` | bootstrap, pairing, cookie, CSRF, session, revoke |
| `WIN` | desktop, launcher, window lifecycle, mobile mode |
| `TERM` | PTY, WebSocket protocol, terminal input/output/resize |
| `FS` | allowed roots dan seluruh operasi filesystem |
| `EDIT` | editor load/save/conflict/dirty state |
| `MON` | metrics, process/session view, quick actions |
| `LAN` | bind, address discovery, laptop pairing, TLS behavior |
| `LIFE` | cleanup, reconnect, race, process group, Android lifecycle |
| `SEC` | abuse cases lintas komponen, headers, limits, secrets |
| `PERF` | size, RSS, startup, responsiveness, throughput |
| `A11Y` | keyboard, focus, semantics, touch target, reduced motion |

Setiap test case menyimpan ID di nama test atau metadata. Buat
`tests/traceability.md` saat implementasi dimulai dengan kolom:

```text
Requirement | Test IDs | Test level | Platforms | Status/evidence
```

Dokumen traceability diperiksa CI agar test ID unik dan semua requirement MVP
memiliki test. Jangan bergantung pada traceability manual tanpa validasi script.

## 4. Test stack

Tool hanya dipakai pada build/development dan tidak ikut ke binary produksi.

### Backend Rust

- Built-in Rust test harness untuk unit dan integration test.
- `cargo nextest` boleh digunakan di CI untuk scheduling/reporting, tetapi
  `cargo test` tetap harus dapat menjalankan suite dasar.
- Property-based testing untuk codec, state machine, dan path input.
- Coverage Rust memakai tool LLVM yang sesuai toolchain yang dikunci.
- Fuzz targets berbasis libFuzzer/cargo-fuzz untuk parser/protocol/path; dijalankan
  nightly, bukan dependency runtime.

### Frontend

- Vitest untuk unit/component test.
- Testing Library untuk behavior DOM dari sudut pengguna; hindari assertion terhadap
  private component state.
- Playwright untuk browser E2E desktop dan mobile viewport.
- Automated accessibility scan ditambah keyboard test manual/Playwright; scanner
  tidak menggantikan pengujian focus dan screen-reader semantics.

### Termux dan LAN

- Real Termux ARM64 device adalah release gate. Emulator boleh untuk smoke test awal,
  tetapi tidak menggantikan device nyata.
- Laptop browser minimal Chromium dan Firefox pada LAN yang sama.
- Device matrix mencatat Android version, Termux version/source, architecture,
  browser version, vendor/device, RAM, dan battery optimization state.
- Gunakan temporary test home/allowed root; jangan menguji destructive operation pada
  home pengguna.

## 5. Test architecture dan determinism

Production boundary harus dapat diinjeksi melalui trait/interface kecil:

- clock untuk token expiry, grace period, dan timeout;
- random source untuk bootstrap, pairing, session, dan WebSocket token;
- network-interface provider untuk IP discovery;
- filesystem root resolver;
- process/PTY adapter;
- metrics provider.

Unit test memakai fake clock dan deterministic RNG yang hanya tersedia melalui test
configuration. Production tidak boleh fallback ke RNG lemah. Integration test PTY,
filesystem, dan HTTP memakai implementation nyata dalam temporary directory.

Ketentuan fixture:

- Setiap test memiliki directory, port, process group, dan session sendiri.
- Bind test memakai port dari OS (`:0`), kecuali test konflik port.
- Cleanup tetap berjalan saat assertion gagal.
- Tidak memakai sleep sebagai sinkronisasi utama. Tunggu event/state dengan timeout
  yang pendek dan error diagnostic.
- Semua timeout memiliki upper bound agar CI tidak menggantung.
- Locale, timezone, terminal size, shell, dan environment penting ditetapkan eksplisit.

## 6. Test pyramid dan CI lanes

### PR fast gate

Target: selesai cepat dan wajib untuk setiap perubahan.

- format/lint/typecheck;
- Rust unit tests;
- frontend unit/component tests;
- protocol and API schema contract tests;
- traceability/test-ID validation;
- build debug dan production frontend;
- secret/log scan serta dependency policy check.

### PR full gate

- Rust integration tests dengan PTY dan filesystem nyata;
- browser E2E Chromium pada desktop dan mobile viewport;
- security corpus dan property tests dengan case count terbatas;
- lifecycle/process-leak test;
- release build size dan idle RSS smoke budget;
- Linux x86_64 full suite dan Android ARM64 cross-build.

### Main/nightly gate

- Firefox E2E;
- extended property tests dan fuzzing time-boxed;
- race/load/reconnect soak tests;
- dependency vulnerability/license audit;
- performance benchmark comparison;
- Android emulator smoke test bila runner tersedia.

### Release gate

- Semua PR/full/nightly test terbaru hijau.
- Termux ARM64 real-device suite hijau.
- HP-to-laptop LAN pairing and terminal E2E hijau.
- Artifact final yang sama dengan calon rilis diuji; jangan rebuild setelah test.
- Size, checksum, SBOM, startup, RSS, dan platform matrix dipublikasikan.

## 7. Coverage policy

Coverage adalah alarm, bukan definisi kualitas.

- Repository target awal: >=80% line dan >=70% branch untuk Rust dan frontend.
- Critical modules `auth`, `paths`, `files`, `protocol`, `session`, dan `pty`:
  >=90% line dan >=85% branch.
- Diff coverage untuk production code baru: >=90%, kecuali generated/platform shim
  dengan alasan yang direview.
- Tidak membuat meaningless assertions atau menghapus branch production hanya untuk
  menaikkan coverage.
- Error path, cancellation, timeout, permission denied, storage full, dan cleanup
  harus diuji walaupun sulit dicapai secara natural.

## 8. Test plan per area

### BOOT — startup, config, dan assets

- `BOOT-001`: default bind hanya `127.0.0.1`.
- `BOOT-002`: `--lan` bind `0.0.0.0` dan menampilkan URL IP private, bukan URL
  `0.0.0.0`.
- `BOOT-003`: port terpakai menghasilkan exit non-zero dan pesan actionable.
- `BOOT-004`: config precedence adalah CLI > config file > environment > default.
- `BOOT-005`: invalid shell/root/certificate ditolak sebelum server menerima request.
- `BOOT-006`: embedded index dan hashed assets memiliki content type/cache header
  benar; SPA fallback tidak menelan endpoint API yang tidak ada.
- `BOOT-007`: Ctrl+C melakukan graceful shutdown dalam budget dan exit code benar.
- `BOOT-008`: production log tidak memuat secret maupun full pairing URL.

### AUTH — bootstrap, pairing, dan session

- `AUTH-001`: local bootstrap secret valid tepat sekali dan segera dihapus dari URL.
- `AUTH-002`: pairing code valid menghasilkan cookie dengan attributes yang benar.
- `AUTH-003`: code salah, expired, reused, atau sudah direvoke ditolak identik tanpa
  membocorkan state.
- `AUTH-004`: attempt limit global/per-IP memblokir brute force tanpa memblokir
  session yang sudah authenticated.
- `AUTH-005`: state-changing request tanpa CSRF token atau dengan token client lain
  ditolak.
- `AUTH-006`: exact Origin/Host diterima; wildcard, suffix trick, missing/malformed,
  dan unauthorized origin ditolak sesuai policy.
- `AUTH-007`: idle dan absolute expiry menutup HTTP session serta semua WebSocket.
- `AUTH-008`: revoke client dari Settings segera menutup terminal dan API client.
- `AUTH-009`: logout hanya merevoke client sendiri.
- `AUTH-010`: concurrent exchange terhadap satu pairing code hanya memiliki satu
  pemenang.
- `AUTH-011`: cookie memiliki `HttpOnly`, `SameSite=Strict`, path yang tepat, dan
  `Secure` pada TLS.
- `AUTH-012`: token/cookie/pairing code tidak muncul dalam log atau client list.

### TERM — PTY dan protocol

- `TERM-001`: codec menerima seluruh frame valid dan menolak type/length invalid.
- `TERM-002`: decoder aman terhadap chunk boundary dan tidak mengalokasikan payload
  di atas limit.
- `TERM-003`: create terminal menghasilkan shell interaktif di working directory yang
  diizinkan.
- `TERM-004`: input UTF-8, control key, paste, dan raw bytes sampai ke PTY tanpa
  transform yang tidak diinginkan.
- `TERM-005`: output parsial/besar sampai berurutan tanpa loss selama client sehat.
- `TERM-006`: resize divalidasi, didebounce, dan ukuran akhir sampai ke PTY.
- `TERM-007`: Ctrl+C mengirim signal ke foreground process, bukan mematikan server.
- `TERM-008`: `nano`, `vim`, `top`/`htop` dapat masuk/keluar alternate screen dan
  terminal kembali normal.
- `TERM-009`: shell exit mengirim EXIT tepat sekali dan UI menunjukkan exit state.
- `TERM-010`: terminal title/control sequence berbahaya tidak menjadi HTML/script.
- `TERM-011`: oversized paste/frame ditolak dengan error dan connection policy tepat.
- `TERM-012`: slow client memicu bounded backpressure tanpa pertumbuhan RAM tanpa
  batas.
- `TERM-013`: `Open Terminal Here` hanya menerima opaque root + relative path valid.

### LIFE — lifecycle dan process cleanup

- `LIFE-001`: close window -> TERM process group -> grace -> KILL bila diperlukan.
- `LIFE-002`: child dan grandchild tidak tertinggal setelah close/server shutdown.
- `LIFE-003`: DELETE berulang idempotent dan cleanup hanya dilakukan sekali.
- `LIFE-004`: disconnect singkat dapat reconnect dalam grace period.
- `LIFE-005`: grace period habis membersihkan session disconnected.
- `LIFE-006`: close, exit, resize, disconnect, dan shutdown bersamaan tidak deadlock,
  panic, double-free, atau membocorkan task.
- `LIFE-007`: browser refresh tidak menduplikasi writer/reader PTY.
- `LIFE-008`: server yang dihentikan Android ditampilkan sebagai disconnected dengan
  recovery action yang benar.
- `LIFE-009`: soak create/use/close ratusan session kembali mendekati baseline RSS dan
  jumlah file descriptor/task/process.

### FS — File Explorer dan allowed roots

- `FS-001`: root id valid dipetakan ke canonical allowed root; root id arbitrary
  ditolak.
- `FS-002`: absolute path, `..`, encoded traversal, double encoding, NUL, separator
  edge case, dan Unicode ambiguity tidak keluar root.
- `FS-003`: symlink ke luar root tidak dapat diikuti untuk read, write, list, copy,
  move, download, upload, atau terminal-here.
- `FS-004`: symlink race antara validation dan operation tidak membuka TOCTOU escape;
  gunakan primitive berbasis directory handle bila platform mendukung.
- `FS-005`: list dipaginasi, stable-sort, dan metadata file special tidak menyebabkan
  hang/crash.
- `FS-006`: create file/folder menolak collision kecuali overwrite policy eksplisit.
- `FS-007`: rename/move atomic pada filesystem sama; cross-filesystem fallback aman
  dan source tidak hilang bila copy gagal.
- `FS-008`: streaming upload/download/copy file besar menjaga bounded memory dan hash
  hasil sama.
- `FS-009`: upload terputus/storage full/permission denied membersihkan temporary file
  dan mempertahankan destination lama.
- `FS-010`: trash dapat memulihkan file; name collision ditangani tanpa overwrite.
- `FS-011`: permanent delete meminta explicit schema flag dan target identity; request
  ambigu ditolak.
- `FS-012`: HTML/SVG/upload content tidak dieksekusi pada origin aplikasi dan response
  memakai `nosniff`/download header.
- `FS-013`: shared storage tidak dapat diakses sebelum menjadi allowed root eksplisit.
- `FS-014`: operasi source/destination memvalidasi kedua root secara independen.
- `FS-015`: search folder tidak mengikuti symlink, dibatasi hasil/waktu, dan dapat
  dibatalkan.

Property/fuzz corpus minimum untuk path:

```text
../x, ..%2fx, %252e%252e, /absolute, \\absolute, a/../../b,
NUL, empty, dot, trailing dot/space, very-long component, invalid UTF-8,
combining Unicode, symlink loop, broken symlink, FIFO, socket, device-like file
```

### EDIT — lightweight editor

- `EDIT-001`: text kecil UTF-8 dibuka dan disimpan byte-correct sesuai newline policy.
- `EDIT-002`: binary/invalid encoding atau file di atas limit tidak dibuka sebagai
  editable text tanpa konfirmasi/mode yang sesuai.
- `EDIT-003`: dirty indicator berubah hanya ketika content berbeda.
- `EDIT-004`: close/reload/navigation dengan dirty content meminta konfirmasi.
- `EDIT-005`: save memakai temporary + atomic rename dan mempertahankan permission yang
  didukung.
- `EDIT-006`: external modification terdeteksi melalui etag/mtime+size dan menampilkan
  conflict; tidak overwrite diam-diam.
- `EDIT-007`: save-as mematuhi allowed-root dan overwrite confirmation.
- `EDIT-008`: failed save mempertahankan buffer editor dan file lama.

### WIN dan A11Y — desktop UI

- `WIN-001`: launcher membuka instance app dengan id/bounds/focus benar.
- `WIN-002`: focus menaikkan z-index tanpa integer growth tak terbatas.
- `WIN-003`: minimize/maximize/restore mempertahankan bounds sebelumnya.
- `WIN-004`: drag/resize tidak membuat title bar hilang seluruhnya dari viewport.
- `WIN-005`: taskbar merepresentasikan semua instance dan active state.
- `WIN-006`: layout valid dipulihkan; data localStorage corrupt/version lama fallback
  aman.
- `WIN-007`: viewport <768 px memakai satu app fullscreen dan task switcher.
- `WIN-008`: orientation/virtual keyboard resize tidak menutupi terminal prompt.
- `WIN-009`: app lazy-load failure menampilkan retry dan tidak merusak desktop.
- `A11Y-001`: seluruh launcher/window action dapat dicapai dengan keyboard.
- `A11Y-002`: focus order, focus trap dialog, focus restore, dan Escape benar.
- `A11Y-003`: button/icon/status memiliki accessible name dan state.
- `A11Y-004`: touch target minimum dan interaction tidak bergantung hover/right-click.
- `A11Y-005`: reduced-motion mematikan animasi non-esensial.

Jangan memakai full-page screenshot sebagai assertion utama. Visual snapshot hanya
untuk layout/theme stabil dan harus dilengkapi assertion behavior/semantics.

### MON — control tools

- `MON-001`: metrics failure/unsupported ditampilkan sebagai unavailable, bukan nol
  palsu.
- `MON-002`: metrics hanya menampilkan session/child milik aplikasi sesuai policy.
- `MON-003`: refresh metrics tidak membuat polling overlap atau leak saat window tutup.
- `MON-004`: Stop All membutuhkan konfirmasi, idempotent, dan memakai lifecycle cleanup.
- `MON-005`: Quick Action menampilkan command sebelum membuka terminal dan tidak
  mengeksekusi shell command tersembunyi.
- `MON-006`: Settings invalid ditolak tanpa merusak config terakhir yang valid.

### LAN — HP ke laptop

- `LAN-001`: `--lan` off tidak dapat diakses melalui IP interface lain.
- `LAN-002`: `--lan` menampilkan seluruh private address valid dan tidak menampilkan
  `0.0.0.0` sebagai URL.
- `LAN-003`: pairing laptop mengaktifkan desktop, filesystem, dan PTY sesuai session.
- `LAN-004`: dua laptop memiliki session terpisah dan revoke salah satu tidak memutus
  yang lain.
- `LAN-005`: network drop/reconnect tidak menduplikasi terminal atau kehilangan cleanup.
- `LAN-006`: TLS certificate/key valid menghasilkan HTTPS/WSS; invalid pair gagal
  sebelum listen.
- `LAN-007`: plain HTTP menampilkan warning dan Clipboard API fallback bekerja.
- `LAN-008`: unauthorized device pada LAN tidak dapat membaca health detail, assets
  sensitif, file, metrics, atau membuka WebSocket.
- `LAN-009`: AP/client isolation atau route failure menghasilkan troubleshooting yang
  actionable tanpa menonaktifkan security.
- `LAN-010`: IP/interface berubah memperbarui display address tanpa melonggarkan Host
  dan Origin policy.

### SEC — defense in depth

- Security header test: CSP ketat, `frame-ancestors 'none'`, `nosniff`, referrer policy,
  cache policy untuk auth/API, dan no permissive CORS.
- WebSocket test: unauthenticated, invalid origin, expired/replayed token, cross-client
  token, oversized/flooded message, idle timeout, logout/revoke closure.
- Injection test: filename, terminal title, error, process label, dan config value
  dianggap text, tidak pernah `innerHTML` atau command shell.
- Resource exhaustion: session, connection, request, upload, search, queue, and file
  descriptor limits mengembalikan error terkontrol.
- Secret hygiene: scan log, URL history setelah exchange, error response, metrics,
  crash report, dan frontend storage.
- Dependency test: known vulnerability, duplicate heavy dependency, unexpected default
  feature, license policy, serta lockfile integrity.

## 9. Performance and low-end tests

Gunakan benchmark device yang tetap dan publish spesifikasinya.

- `PERF-001`: compressed Termux artifact target <=10 MiB, hard gate <=50 MiB.
- `PERF-002`: frontend Brotli/gzip target <=750 KiB.
- `PERF-003`: server idle RSS target <=35 MiB, hard gate <=50 MiB.
- `PERF-004`: cold startup sampai health-ready target <=1 detik.
- `PERF-005`: empat terminal aktif pada 2 core/1 GiB tetap responsif.
- `PERF-006`: File Explorer folder besar dipaginasi tanpa long task UI berlebihan.
- `PERF-007`: upload/download/copy besar memakai bounded RSS.
- `PERF-008`: minimized/hidden app tidak menjalankan animation/polling loop tidak perlu.
- `PERF-009`: 30 menit output terminal dan reconnect tidak menunjukkan growth terus-
  menerus pada RSS, task, FD, DOM node, atau listener.

Performance gate memakai baseline commit dan tolerance terdokumentasi agar variasi
runner tidak membuat flaky test. Hard budget selalu berlaku tanpa tolerance.

## 12. Evidence dan definition of tested

Sebuah requirement dianggap tested hanya bila:

- test memiliki ID unik dan assertion terhadap behavior nyata;
- test pernah terlihat gagal pada kondisi yang hendak dicegah;
- test lulus pada platform yang diklaim;
- tidak bergantung pada retry atau timing kebetulan;
- cleanup dan negative/error path relevan ikut diuji;
- traceability menunjuk ke hasil CI/device run;
- untuk security/performance critical behavior, bukti mencakup test khususnya, bukan
  hanya coverage umum.

V1 tidak boleh dirilis bila ada test wajib gagal, flaky yang belum diselesaikan,
critical path di bawah coverage gate, process/file leak, path escape, auth bypass,
atau hard performance budget terlewati.
