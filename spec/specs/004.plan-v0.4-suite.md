## 1. Latar Belakang dan Risiko

Dengan dirilisnya **v0.3.0** (Terminal Resizing & Window Control Hardening, per
[`003.plan-v0.3-terminal-resize.md`](./003.plan-v0.3-terminal-resize.md)), Mux Web UI
telah memiliki fondasi desktop multi-window, PTY interaktif dengan session persistence
(ring buffer 256KB), autentikasi pairing code/cookie rotasi, serta file manager dan text
editor dalam sandbox filesystem yang ketat.

Namun, alur kerja developer harian di Linux & Termux masih terfragmentasi:
1. **Manajemen Git**: Developer harus beralih bolak-balik antara Text Editor dan Terminal
   hanya untuk memeriksa status file yang berubah (`git status`), meninjau diff baris
   demi baris, staging, commit, atau push/pull.
2. **Manajemen Paket Sistem**: Menginstall tools atau dependencies di Termux (`pkg`) atau
   Linux (`apt`/`pacman`/`apk`) membutuhkan terminal manual tanpa visibilitas visual
   terhadap paket terpasang, pembaruan yang tersedia, atau pencarian repositori.
3. **Kolaborasi & Sharing**: Skenario berbagi output terminal secara live (misalnya
   memperlihatkan log build/server yang berjalan kepada rekan) atau berbagi file/folder
   tertentu secara aman tanpa memberikan hak akses eksekusi penuh (shell/write) belum
   tersedia (Milestone D pada `001.plan-v0.2.md` tertunda).
4. **Manipulasi Arsip (Zip/Tar)**: Mendownload repositori atau asset terkompresi (.zip,
   .tar.gz) tidak dapat diekstrak atau dibuat secara visual dari File Explorer, memaksa
   penggunaan command-line mentah yang rawan jebakan direktori.

### 1.1 Fakta Kode v0.3 yang Menjadi Titik Awal

- **Filesystem Sandbox (`src/paths.rs:45-151`)**: Sistem `AllowedRoots` memetakan `root_id`
  (seperti `"home"`) ke direktori fisik ter-canonicalize. Setiap path wajib berada di dalam
  root yang diizinkan dan menolak `..`, symlink escape, serta hardlink escape (`nlink > 1`).
  Operasi Git dan Archive Manager **wajib** menggunakan validasi `AllowedRoots` yang sama.
- **PTY Session Infrastructure (`src/pty.rs`, `src/session.rs`)**: Mux Web UI telah memiliki
  PTY spawner dengan deteksi shell otomatis, channel I/O streaming, dan `SessionRegistry`
  berbasis ring buffer. Fitur interaktif seperti Package Manager (yang membutuhkan `sudo`
  atau konfirmasi `[Y/n]`) dan Git Remote (yang meminta passphrase/token) dapat memanfaatkan
  sub-session PTY streaming atau command runner yang aman.
- **HTTP Routing & API (`src/http.rs:40-100`)**: Router Axum telah menerapkan autentikasi
  `auth_middleware`, Host/Origin pinning (`host_origin_middleware`), dan WebSocket codec biner.
  Endpoint v0.4 akan ditambahkan sebagai resource REST `/api/v1/git/*`, `/api/v1/packages/*`,
  `/api/v1/share/*`, dan `/api/v1/archive/*`.
- **Frontend Architecture (`web/src/desktop/*`)**: Window manager Preact telah mendukung
  window instance tracking, z-index focus ordering, dragging, 8-way resizing, dan dynamic
  app mounting. App baru (`GitView`, `PackageCenterView`, `ArchiveModal`, `ShareModal`) akan
  diintegrasikan ke dalam app registry desktop.
- **Graph Knowledge Base (`graphify-out/GRAPH_REPORT.md:14`)**: 736 nodes / 1286 edges / 37 communities (2026-08-19, commit `1592b060`). `http.rs` cohesion `0.11` — sinyal perlu modularisasi sebelum ekspansi v0.4.

## 3. Threat Model & Security Boundaries

### 3.1 Inti v0.4 (Dipertahankan dari Audit Awal)

| Attacker / Skenario | Vektor Ancaman | Pertahanan Wajib Mux Web UI (v0.4) |
|---|---|---|
| **Malicious Repository / Git Injection** | Parameter branch name, remote URL, atau commit message mengandung control characters / shell metacharacters (`$(rm -rf)`, `;`, `\n`). | **No shell execution**: Git dieksekusi via `std::process::Command` langsung dengan argumen array terpisah (`["status", "--porcelain"]`), tidak pernah dilewatkan ke `sh -c`. Validasi nama branch (`git check-ref-format --normalize`). |
| **Repository Escape** | Submodule atau path git file mencoba mengarah ke luar `AllowedRoots`. | Seluruh repo path diverifikasi terlebih dahulu melalui `AllowedRoots::resolve_path`. |
| **Zip-Slip Traversal** | File arsip jahat mengandung header path `../../../../etc/passwd` atau symlink ke direktori sistem. | Sanitasi header arsip: ekstrak hanya komponen relatif, tolak absolut/`..`, tolak pembuatan symlink yang menunjuk ke luar target destination directory (`ARC-004`). |
| **Zip-Bomb DoS** | Arsip kecil (misal 1MB) yang membengkak menjadi puluhan gigabyte saat diekstrak, memenuhi storage atau menghabiskan RAM host. | **Strict decompression budgets**: Max total extracted size (default 500MB), max file count (default 10,000 files), max expansion ratio (default 100:1). Ekstraksi dihentikan seketika saat budget terlampaui (`ARC-005`). |
| **Package Command Injection** | Nama paket manipulatif mengandung parameter shell (e.g. `curl; reboot`). | Validasi regex ketat nama paket: `^[a-zA-Z0-9][a-zA-Z0-9+._-]*$`. Eksekusi langsung via argv tanpa shell (`PKG-006`). |
| **Unauthorized Share Link Tampering** | Pengguna luar dengan share link mencoba menulis file atau mengirim input terminal. | Endpoint share link dibatasi middleware `ReadOnlyGuard`: semua HTTP request non-GET/HEAD ditolak (403), WebSocket frame selain Ping/Pong dan Close langsung di-drop (`SHR-003`). |
| **Capability Token Guessing** | Penyerang menebak token share link publik. | Token share di-generate menggunakan CSPRNG minimal 32 byte (256-bit entropy, base64url/hex), diverifikasi dengan perbandingan constant-time, dan memiliki configurable TTL (`SHR-002`). |

## 4. Milestone A — Git UI (Visual Version Control)

### A.1 Kemampuan Inti
1. **Repository Discovery & Status (`GIT-001`)**:
   - Deteksi repositori Git aktif pada direktori kerja file explorer atau root yang dipilih.
   - Endpoint `GET /api/v1/git/status?root=<root_id>&path=<repo_subpath>`:
     - Mengembalikan branch aktif, remote tracking branch (`origin/main`), count ahead/behind.
     - Mengembalikan daftar staged, unstaged, dan untracked files dengan status kode porcelain v2.
2. **Visual Diff Viewer (`GIT-002`)**:
   - Endpoint `GET /api/v1/git/diff?root=<root_id>&path=<repo_subpath>&file=<file_path>&staged=<bool>`:
     - Mengembalikan unified diff terstruktur (hunks, line numbers, added/removed lines).
   - Frontend UI: Side-by-side atau Unified diff viewer dengan warna baris hijau/merah dan navigasi antar perubahan.
3. **Staging & Unstaging (`GIT-003`)**:
   - Endpoint `POST /api/v1/git/stage`: Stage single file, stage all (`git add -A`), unstage single file (`git restore --staged`), discard changes (`git restore`).
4. **Commit Creation (`GIT-004`)**:
   - Endpoint `POST /api/v1/git/commit`: Menerima pesan commit, opsi `--amend`, dan mengembalikan SHA commit baru.
5. **Branch Management (`GIT-005`)**:
   - Endpoint `GET /api/v1/git/branches` & `POST /api/v1/git/branch/checkout`: List local/remote branches, checkout branch, dan buat branch baru.
6. **Remote Operations via Streaming Runner (`GIT-006`)**:
   - Endpoint `POST /api/v1/git/remote/action` (`fetch`, `pull`, `push`):
   - Jika remote membutuhkan autentikasi interaktif (SSH passphrase / HTTPS token), aksi dapat dialihkan ke temporary PTY session atau streaming WebSocket agar pengguna dapat menginput credential tanpa blocking server.

### A.2 Acceptance Criteria Milestone A
- [ ] `GIT-001`: `GET /api/v1/git/status` mengembalikan representasi JSON akurat dari `git status --porcelain=v2`.
- [ ] `GIT-002`: `GET /api/v1/git/diff` mengembalikan hunks parsed dengan nomor baris lama dan baru yang valid.
- [ ] `GIT-003`: Staging dan unstaging mengubah state file di index git tanpa memodifikasi file lain.
- [ ] `GIT-004`: Pembuatan commit menghasilkan commit git valid dengan author default git config.
- [ ] `GIT-005`: Checkout branch berhasil beralih branch dan memperbarui status UI.
- [ ] `GIT-006`: Semua panggilan command git tidak menggunakan shell parsing (`sh -c`) dan aman dari injection.
- [ ] `GIT-007`: Direktori di luar `AllowedRoots` ditolak dengan `400 Bad Request / Path Traversal`.
- [ ] `GIT-008` *(baru, hardening)*: Session/attach token untuk Git remote PTY memakai CSPRNG post-H1 (tidak ada nanos).

## 5. Milestone B — Package Center (Visual Package Management)

### B.1 Multi-Backend Architecture
1. **Platform Auto-Detection (`PKG-001`)**:
   - Server mendeteksi package manager yang tersedia pada host:
     - **Termux**: `pkg` (wrapper `apt`) / `apt`
     - **Debian / Ubuntu**: `apt` / `apt-get`
     - **Arch Linux / Manjaro**: `pacman`
     - **Alpine Linux**: `apk`
   - Endpoint `GET /api/v1/packages/backend`: Mengembalikan backend aktif dan capabilities (root required, update support).
2. **List & Search Packages (`PKG-002`, `PKG-003`)**:
   - Endpoint `GET /api/v1/packages/installed`: Daftar paket terpasang beserta versi.
   - Endpoint `GET /api/v1/packages/upgradable`: Daftar paket yang memiliki versi baru.
   - Endpoint `GET /api/v1/packages/search?q=<query>`: Mencari paket di repositori upstream.
3. **Interactive / Streaming Task Runner (`PKG-004`)**:
   - Operasi `install`, `remove`, `upgrade`, dan `update-index` memicu runner proses streaming.
   - Output instalasi dialirkan real-time ke UI melalui WebSocket task stream (`/api/v1/packages/stream/<task_id>`).
   - Jika prompt interaktif muncul (`Do you want to continue? [Y/n]`), UI menyediakan tombol aksi cepat atau input pass-through.

### B.2 Acceptance Criteria Milestone B
- [ ] `PKG-001`: Auto-detection memilih backend yang benar sesuai OS (`pkg` di Termux, `apt`/`pacman` di Linux).
- [ ] `PKG-002`: Listing paket terpasang mengembalikan array nama paket, versi terpasang, dan deskripsi singkat.
- [ ] `PKG-003`: Pencarian repositori membatasi query minimal 2 karakter dan menolak karakter berbahaya.
- [ ] `PKG-004`: Task stream mengirimkan log keluaran stdout/stderr secara real-time dan melaporkan exit code terminal.
- [ ] `PKG-005`: Input nama paket diverifikasi dengan regex `^[a-zA-Z0-9][a-zA-Z0-9+._-]*$` + tanpa shell.
- [ ] `PKG-006` *(baru, hardening)*: Seluruh `install/remove` dieksekusi via `Command` argv terpisah; tidak ada `sh -c` di `src/packages.rs`.

> **Keputusan tertunda (dikonfirmasi Opsi A):** Package Center di fase akhir (`v0.4.2`) dan **tanpa `sudo` interaktif otomatis** pada iterasi pertama — hanya operasi yang tidak butuh privilege atau display prompt eksplisit. `sudo` via PTY ditunda ke `v0.5`.

## 6. Milestone C — Read-only Share Links (Capability Sharing)

### C.1 Desain Protokol & Keamanan
1. **Capability Token Generation (`SHR-001`, `SHR-002`)**:
   - Endpoint `POST /api/v1/share/create`:
     - Payload: `{ target_type: "terminal" | "file" | "folder", target_id: string, path?: string, ttl_seconds?: number, max_views?: number }`
     - Response: `{ share_token: string, share_url: string, expires_at: number }`
   - Token di-generate dengan 32 bytes CSPRNG (`getrandom`, bukan `rand_id` nanos), disimpan di in-memory `ShareRegistry`.
2. **Read-only Terminal Broadcast (`SHR-003`)**:
   - Akses via `/share/terminal/<share_token>`:
     - WebSocket route: `/api/v1/share/ws/terminal/<share_token>`
     - Mengirim replay ring buffer dan live broadcast output.
     - **Penolakan Input Keras**: Setiap frame `Input` atau `Resize` dari client share langsung diabaikan / koneksi ditutup jika melanggar.
3. **Read-only File & Folder Viewer (`SHR-004`)**:
   - Akses via `/share/file/<share_token>` dan `/share/folder/<share_token>`:
     - Membuka viewer khusus tanpa kontrol editor, tanpa tombol save, tanpa delete/rename.
4. **Revocation & Lifecycle (`SHR-005`)**:
   - Endpoint `DELETE /api/v1/share/<share_token>`: Revokasi instan dari Settings atau launcher.
   - Otomatis hangus saat TTL kedaluwarsa atau `max_views` tercapai.

### C.2 Acceptance Criteria Milestone C
- [ ] `SHR-001`: Pembuatan share link menghasilkan token acak 256-bit unik dan terdaftar di `ShareRegistry` (CSPRNG, bukan nanos).
- [ ] `SHR-002`: Request share link tanpa token valid atau dengan token kedaluwarsa ditolak (404/401) dengan constant-time compare.
- [ ] `SHR-003`: Client terminal share menerima output stream tetapi transmisi frame `Input` tidak pernah diteruskan ke PTY master.
- [ ] `SHR-004`: Client file share dapat membaca dan mendownload konten file target tetapi tidak dapat menulis/mengubah (GET/HEAD only).
- [ ] `SHR-005`: Revokasi share link seketika memutuskan koneksi aktif dan menolak request berikutnya.
- [ ] `SHR-006` *(baru, hardening)*: `ReadOnlyGuard` menolak non-GET/HEAD + drop WS Input/Resize dengan log `tracing::warn`.

## 7. Milestone D — Archive Manager (Safe Compression & Extraction)

### D.1 Format & Proteksi Ekstraksi
1. **Archive Inspection (`ARC-001`)**:
   - Endpoint `GET /api/v1/archive/inspect?root=<root_id>&path=<archive_path>`:
     - Menganalisis isi berkas (.zip, .tar, .tar.gz, .tgz, .tar.bz2, .tar.xz) tanpa mengekstrak ke disk.
     - Mengembalikan daftar file/folder, ukuran uncompressed, dan total file count.
2. **Safe Extraction Sandbox (`ARC-002`, `ARC-004`)**:
   - Endpoint `POST /api/v1/archive/extract`:
     - Payload: `{ root: string, archive_path: string, destination_dir: string, overwrite: bool }`
     - **Anti Zip-Slip**: Setiap header entry dinormalisasi; komponen `..` atau prefix root absolut dihapus. Hasil path harus terverifikasi berada di dalam `destination_dir` via `AllowedRoots::resolve_path`.
     - **Symlink Quarantine**: Symlink di dalam arsip yang menunjuk ke luar `destination_dir` ditolak dan dilewati.
3. **Anti Zip-Bomb Enforcement (`ARC-005`)**:
   - Pengawas dekompresi streaming memonitor akumulasi byte yang ditulis:
     - `MAX_EXTRACT_BYTES`: Default 500 MiB (configurable).
     - `MAX_EXTRACT_FILES`: Default 10,000 files.
     - `MAX_EXPANSION_RATIO`: Default 100:1.
   - Jika salah satu batas terlampaui, proses ekstraksi langsung dihentikan (`Err(ZipBombDetected)`), file temporer dibersihkan, dan status `413 Payload Too Large / 400 Bad Request` dikembalikan.
4. **Archive Creation (`ARC-006`)**:
   - Endpoint `POST /api/v1/archive/create`:
     - Membuat berkas `.zip` atau `.tar.gz` dari daftar file/folder terpilih di dalam sandbox.

### D.2 Acceptance Criteria Milestone D
- [ ] `ARC-001`: Inspect arsip mengembalikan struktur pohon entri dan total kalkulasi ukuran.
- [ ] `ARC-002`: Ekstraksi file zip/tar normal mengekstrak berkas ke direktori tujuan dengan permission yang aman.
- [ ] `ARC-004`: Arsip dengan path traversal berbahaya (`../../secret.txt`) ditolak dan tidak pernah menulis di luar destination.

## 11. Bukan Scope (Out of Scope v0.4)

1. **Full Git Merge Conflict Resolution GUI**: Hanya visual 3-way diff dasar; merge conflict interaktif penuh diserahkan ke terminal/editor eksternal.
2. **Multi-User Role-Based Access Control (RBAC)**: Share links bersifat capability token acak; autentikasi multi-user dengan login database tetap di luar scope.
3. **Arbitrary Package Repositories / PPA Management**: Menambah repositori pihak ketiga custom tetap dikelola via shell/terminal.
4. **Proprietary Archive Formats (.rar, .7z dengan enkripsi khusus)**: v0.4 fokus pada format standar universal (.zip, .tar, .tar.gz, .tgz, .tar.bz2, .tar.xz).
5. **GPG/cosign installer signature (`M4`)**: Dicatat, implementasi tunda ke `v0.5` (supply chain hardening lanjutan).
6. **Package `sudo` interaktif otomatis**: Tunda ke `v0.5` — `v0.4.2` hanya operasi non-privileged.
