## 1. Latar Belakang dan Fakta Kode

Pada v0.1 dan v0.2, terminal PTY dan xterm.js telah terhubung menggunakan protokol WebSocket biner (`Frame::Resize { cols, rows }`, opcode `0x02`). Namun, terdapat beberapa celah kritis pada pipeline resize saat ini:

### 1.1 Fakta Kode Titik Awal
- `src/pty.rs:287-309`: `PtySession::resize(&self, cols: u16, rows: u16)` langsung memanggil `libc::ioctl(TIOCSWINSZ)` tanpa validasi atau pembatasan (clamping) nilai `cols` dan `rows`. Jika client mengirim `cols=0` atau `rows=0` atau `65535`, ioctl dapat gagal atau menghasilkan perilaku terminal yang tidak terdefinisi di kernel PTY driver.
- `src/http.rs:34-37, 364`: `CreateTerminalReq` menerima `cols: Option<u16>` dan `rows: Option<u16>` tanpa validasi batas minimum/maksimum sebelum membuat sesi PTY.
- `src/http.rs:655-660`: Pada `handle_terminal_ws`, frame `Frame::Resize` menelan error resize dengan `let _ = session_in.pty.resize(...)` tanpa logging atau penanganan error.
- `web/src/apps/terminal/TerminalView.tsx:112-123`: `ResizeObserver` memanggil `fitAddon.fit()` dan langsung mengirim `sendResize` ke WebSocket tanpa debounce. Saat pengguna melakukan drag resize pada window, puluhan hingga ratusan frame WebSocket terkirim dalam waktu singkat (resize flood).
- `web/src/apps/terminal/TerminalView.tsx:38`: `fitAddon.fit()` dipanggil tanpa pengecekan apakah container element memiliki ukuran `0x0` (misal saat diminimalkan atau sebelum DOM ter-render), yang dapat memicu warning atau layout exception.
- `web/src/desktop/WindowFrame.tsx:24-54`: WindowFrame saat ini hanya mendukung dragging melalui `.window-header`. Tidak ada resize handle di tepi atau sudut window untuk mengubah ukuran window secara interaktif.
- `tests/traceability.md`: Requirement `TERM-006` telah ditandai Passed sebagai baseline sinyal, namun requirement komprehensif untuk validasi, debounce, window handle, dan robustness (Family `RSZ`) belum terdaftar.

## 3. Threat Model

| Vektor Ancaman | Dampak | Mitigasi |
|---|---|---|
| Resize flood DoS | Client mengirim ribuan frame RESIZE per detik untuk membebani CPU / lock contention | Frontend debounce (~75ms) + backpressure bounded WebSocket di backend (`RSZ-004`, `RSZ-006`) |
| Nilai ekstrem / 0 | `cols=0` atau `rows=0` atau `u16::MAX` menyebabkan crash ioctl atau kernel PTY panic | Clamping keras di backend (`MIN_COLS=2, MAX_COLS=500, MIN_ROWS=1, MAX_ROWS=200`) (`RSZ-002`, `RSZ-003`) |
| Window collapse | Dragging window menjadi ukuran 0x0 merusak layout dan xterm canvas | Window minimum bounds clamping (`minWidth=240, minHeight=140`) di `WindowFrame.tsx` (`RSZ-008`) |

## 4. Milestone A — Backend Dimension Clamping & Robustness

### A.1 Batas Dimensi (Constants)
```rust
pub const MIN_COLS: u16 = 2;
pub const MAX_COLS: u16 = 500;
pub const MIN_ROWS: u16 = 1;
pub const MAX_ROWS: u16 = 200;
pub const DEFAULT_COLS: u16 = 80;
pub const DEFAULT_ROWS: u16 = 24;

pub fn clamp_dimensions(cols: u16, rows: u16) -> (u16, u16) {
    (cols.clamp(MIN_COLS, MAX_COLS), rows.clamp(MIN_ROWS, MAX_ROWS))
}
```

### A.2 Perilaku Sesi dan Sinyal
- `PtySession::new` dan `PtySession::resize` secara deterministik meng-clamp nilai ke rentang aman sebelum memanggil `ioctl(TIOCSWINSZ)`.
- Jika sesi PTY sudah ditutup / exit, panggilan resize mengembalikan error Result tanpa menyebabkan panic atau deadlock.
- Metadata sesi (`meta.cols`, `meta.rows`) diperbarui hanya dengan nilai yang sudah tervalidasi.

## 5. Milestone B — Frontend Window Resize Handles & Debounce

### B.1 WindowFrame 8-Way Resizing
- Menambahkan 8 resize zone pada `WindowFrame.tsx`:
  - Edges: `n` (top), `s` (bottom), `e` (right), `w` (left).
  - Corners: `ne`, `nw`, `se`, `sw`.
  - Visible corner grip di kanan-bawah.
- Menggunakan Pointer Events (`setPointerCapture` / `releasePointerCapture`) untuk kompatibilitas mouse dan layar sentuh Android/Termux.
- Clamping ukuran minimum window: `width >= 240px`, `height >= 140px`.

### B.2 TerminalView Debounced Fit
- `ResizeObserver` menjalankan debouncer trailing-edge (~75ms).
- Memeriksa `clientWidth > 0 && clientHeight > 0` sebelum menjalankan `fitAddon.fit()`.
- Mengirim frame `0x02 RESIZE` hanya saat ukuran kolom atau baris xterm benar-benar berubah.
