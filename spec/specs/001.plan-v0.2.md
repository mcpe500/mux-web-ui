# Mux Web UI — v0.2 plan: Auth + TLS, Session Persistence, Test Suite & CI

Status: proposed  
Target: Linux x86_64/ARM64 dan Termux/Android ARM64  
Brand: QA / test automation — v0.2 adalah "I shipped it, then I QA'd my own project."

Dokumen ini wajib dikerjakan dengan test-driven development mengikuti
[`000a.plan-test.md`](./000a.plan-test.md) dan diperiksa dengan checklist
mengikuti pola [`000b.plan-checklist.md`](./000b.plan-checklist.md). Sebuah
milestone belum selesai hanya karena UI terlihat bekerja; seluruh acceptance
test terkait harus lebih dahulu lulus.

## 1. Latar belakang dan risiko

v0.1 (lihat [`000.plan.md`](./000.plan.md) dan `000b.plan-checklist.md`)
menghasilkan binary tunggal yang membuka port dengan PTY interaktif. README
menyorot containment path traversal, tetapi autentikasi belum disebut dan
belum diimplementasikan. Tanpa token atau password, siapa pun pada jaringan
yang sama dapat membuka shell di perangkat — di Termux pada hotspot publik
ini risiko nyata, bukan teoritis.

v0.2 menutup celah tersebut dan menjadikan kualitas test sebagai pembeda:

1. **Auth + TLS** — dikerjakan pertama.
2. **Session persistence (detach/reattach)** — nama produk adalah Mux;
   menutup tab tidak boleh membunuh PTY.
3. **Test suite + CI** — regression test untuk seluruh traversal vector dan
   integration test WebSocket PTY, dijalankan pada matrix CI.
4. **(Opsional) upload/download file.**
5. **(Opsional) read-only share links.**

Scope v0.2 wajib: auth + TLS + test suite. Item 4 dan 5 hanya dikerjakan
bila scope wajib selesai lebih cepat dari perkiraan.

## 2. Hubungan dengan rencana v1

`000.plan.md` sudah menspesifikasikan arsitektur auth (bagian 6: endpoint
`/api/v1/auth/*`, cookie, pairing code; bagian 8: keamanan minimum) dan
`tests/traceability.md` sudah mendefinisikan keluarga requirement AUTH-001..
012, LAN-001..008, SEC-001..002, LIFE-004/LIFE-005. v0.2 adalah implementasi
nyata dari spesifikasi tersebut yang belum dikerjakan, ditambah keluarga
requirement baru untuk persistence dan CI. Requirement baru:

| Keluarga | ID | Kebutuhan |
|---|---|---|
| Session persistence | SESS-001..006 | detach/reattach, reattach ulang, daftar session, limit idle, batas jumlah session, reconnect tanpa duplikasi reader/writer |
| CI/CD | CI-001..005 | matrix build, traversal regression, WS integration, budget gate, artifact checksum |

## 3. Milestone A — Autentikasi + TLS

### A.1 Autentikasi dasar

- Server mencetak token bearer acak saat startup di mode local
  (bootstrap secret, single-use, sesuai `AUTH-001`).
- Pertukaran token menjadi session cookie `HttpOnly`, `SameSite=Strict`,
  dan `Secure` ketika TLS aktif; credential tidak disimpan di
  `localStorage` atau URL setelah pairing selesai (`AUTH-002`, `AUTH-011`).
- Penolakan pairing dilakukan dalam constant time (`AUTH-003`).
- Rate limit global dan per-IP pada endpoint auth (`AUTH-004`).
- CSRF token untuk semua state-changing request; validasi exact `Origin`
  dan `Host` pada HTTP dan WebSocket upgrade (`AUTH-005`, `AUTH-006`).
- Session terikat ke client record, idle/absolute expiry, revocable;
  revocation langsung menutup seluruh WebSocket client (`AUTH-007`,
  `AUTH-008`, `AUTH-009`, `AUTH-010`).
- Secret tidak pernah muncul di log atau response (`AUTH-012`, `SEC-001`).

### A.2 TLS

- `--tls-cert <path> --tls-key <path>` mengaktifkan HTTPS/WSS (`LAN-006`).
- `--generate-cert` membuat self-signed certificate sementara untuk
  development/pairing, dengan warning yang jelas di output.
- Warning besar ditampilkan ketika bind non-loopback aktif tanpa TLS.

### A.3 Bind default dan mode eksplisit

- Bind default tetap `127.0.0.1` (`BOOT-001`).
- `--host 0.0.0.0` adalah opt-in eksplisit; `--lan` tetap ada sebagai
  shortcut dengan deteksi/display IP private (`BOOT-002`, `LAN-002`).
- Endpoint `/api/v1/auth/clients` dan revoke tersedia di Settings
  (`AUTH-008`).

### A.4 README

README harus menyebut auth secara eksplisit: token startup, cookie session,
TLS, dan default bind loopback. Kalimat yang tepat (contoh): "Every session
is authenticated; default bind is loopback-only." Orang akan mengasumsikan
auth tidak ada bila tidak dibaca.

### A.5 Acceptance criteria Milestone A

- `AUTH-001..012`, `BOOT-001`, `BOOT-002`, `LAN-002`, `LAN-006`,
  `SEC-001` lulus di Linux; uji device Termux dijalankan bila perangkat
  tersedia.
- Default server tidak dapat diakses dari jaringan lain.
- README menampilkan bagian "Security & Authentication" dengan tiga poin:
  token, TLS, loopback default.

## 4. Milestone B — Session persistence (detach/reattach)

### B.1 Perilaku

- Menutup tab / disconnect WebSocket tidak membunuh PTY; session tetap
  hidup dalam reconnect grace period (`LIFE-004`).
- Session dapat di-dettach dari satu client dan di-reattach dari client
  lain (tab baru atau browser lain) selama masih hidup (`SESS-001`,
  `SESS-002`).
- Refresh halaman tidak menduplikasi reader/writer PTY (`LIFE-007`,
  `SESS-006`).
- UI menampilkan daftar session aktif (id, shell, umur, attach count) dan
  tombol attach/detach per session (`SESS-003`).
- Idle session tanpa client diputus setelah grace period; session yang
  dilekatkan kembali dipertahankan (`LIFE-005`, `SESS-004`).
- Batas jumlah session aktif tetap berlaku; session reattach dihitung
  dalam limit (`SESS-005`).
- Output memakai bounded channel; client lambat diputus dengan error yang
  jelas, bukan RAM yang tumbuh tanpa batas (lihat bagian 7 `000.plan.md`).

### B.2 API

- `POST /api/v1/terminals` mengembalikan `session_id` yang bertahan dari
  pembuatan sampai terminasi.
- `GET /api/v1/terminals` mendaftar session yang masih hidup beserta
  metadata (tanpa secret).
- `GET /api/v1/terminals/{id}/ws?token=...` menerima reattach dengan token
  single-use baru; token lama dianggap invalid setelah attach pertama
  (`AUTH` session-scoped token; lihat bagian 6 `000.plan.md`).

### B.3 Acceptance criteria Milestone B

- Test integration membuktikan: connect → disconnect → reconnect dalam
  grace period → output berlanjut tanpa duplikasi.
- Test membuktikan: detach dari client A, attach dari client B, output
  tetap satu stream yang sama.
- `SESS-001..006`, `LIFE-004`, `LIFE-005`, `LIFE-007` lulus.
- Tidak ada child process yatim setelah semua jalur close (regression
  `LIFE-002`).

## 5. Milestone C — Test suite + CI

### C.1 Regression traversal vector

Test unit + integration untuk setiap vector yang diblokir:

- `..` dan varian encoded (`%2f`, `%2e%2e`, double encoding) — `FS-002`.
- Symlink escape keluar allowed root; symlink ke allowed root lain
  ditampilkan sebagai symlink (`FS-003`, `FS-004`).
- NUL byte dan path absolute — tolak sebelum canonicalize.
- `root_id + relative_path` selalu dicanonicalize dua kali: target dan
  parent, untuk move/copy lintas root (`FS-014`).
- Race TOCTOU symlink diuji dengan reproducer deterministik (`FS-004`).

### C.2 Integration WebSocket PTY

- Codec frame biner valid/invalid (`TERM-001`, `TERM-002`).
- Spawn shell, input/output/resize, exit, close (`TERM-003`..`TERM-009`).
- Oversized frame/paste ditolak (`TERM-011`), bounded backpressure
  (`TERM-012`), control sequence tidak disuntikkan ke DOM (`TERM-010`).
- Cleanup process group setelah close/shutdown (`LIFE-001`, `LIFE-002`).

### C.3 CI GitHub Actions

- Matrix target: `x86_64-unknown-linux-gnu` dan `aarch64-linux-android`
  (cross-compile check; smoke test Termux nyata bila runner tersedia).
- Job test: `cargo test` seluruh suite (unit + integration) di kedua
  target yang dapat dijalankan.
- Job budget gate: `scripts/check_budget.sh` dan laporan binary
  size/RSS sebagai artifact (`PERF-001..003`).
- Artifact release + checksum; ubuntu runner; cache cargo.
- Flaky test diperlakukan sebagai bug (aturan `000a.plan-test.md`); retry
  hanya alat diagnosis, bukan hasil pass resmi.
- `CI-001..005` tercatat di `tests/traceability.md`.

### C.4 Acceptance criteria Milestone C

- Seluruh traversal vector regression lulus di CI matrix.
- Integration WS PTY lulus di Linux x86_64 dan ARM64.
- Budget gate hijau dan artifact ter-upload di setiap push ke `main`.

## 6. Milestone D (opsional) — Upload/download & share links

Dikerjakan hanya bila A, B, C selesai.

- **Upload/download**: streaming dengan batas ukuran, temporary file,
  fsync bila tersedia, atomic rename, `Content-Disposition` +
  `X-Content-Type-Options: nosniff` (`FS-008`, `FS-012`, `FS-009`).
- **Read-only share links**: token sekali pakai berumur pendek, scope
  file tunggal, tanpa akses shell; audit log tanpa secret.

## 7. Urutan pengerjaan (TDD)

Mengikuti pola `000a.plan-test.md`: Red → Green → Refactor untuk setiap
item, bukti test pada CI atau device test.

1. Regression test traversal vector yang sudah diblokir (harus hijau sejak
   awal — melindungi perilaku v0.1).
2. Red: test auth gagal (tanpa token → 401, tanpa TLS → warning, bind
   non-loopback → warning). Green: implementasi Milestone A.
3. Red: test detach/reattach gagal (disconnect membunuh PTY). Green:
   implementasi Milestone B.
4. Setup CI matrix dan jalankan seluruh suite; perbaiki flaky.
5. Update `tests/traceability.md` status dari Planned → Passed.
6. README: tambahkan bagian Security & Authentication.
7. Bila sisa waktu: Milestone D.

## 8. Definition of done v0.2

- Seluruh test AUTH/SESS/FS/TERM/LIFE yang tercantum lulus di CI.
- Default bind loopback; `--host 0.0.0.0` hanya dengan auth aktif dan
  warning TLS bila plain HTTP.
- Menutup tab tidak membunuh PTY; reattach bekerja dari tab/browser lain.
- README menyebutkan auth, TLS, dan persistence secara eksplisit.
- Tidak ada proses yatim pada semua jalur close yang diuji.
- Tidak ada secret pada log, URL, atau localStorage setelah pairing.
