# Mux Web UI — v0.2 plan: Auth + TLS, Session Persistence, Test Suite & CI

Status: proposed  
Target: Linux x86_64/ARM64 dan Termux/Android ARM64  
Brand: QA / test automation — v0.2 adalah "I shipped it, then I QA'd my own project."

Dokumen ini wajib dikerjakan dengan test-driven development mengikuti
[`000a.plan-test.md`](./000a.plan-test.md) dan diperiksa dengan checklist
mengikuti pola [`000b.plan-checklist.md`](./000b.plan-checklist.md). Sebuah
milestone belum selesai hanya karena UI terlihat bekerja; seluruh acceptance
test terkait harus lebih dahulu lulus. Checklist pelaksanaan v0.2 dicatat di
`001b.plan-checklist.md` (dibuat saat implementasi dimulai).

## 1. Latar belakang dan risiko

v0.1 (lihat [`000.plan.md`](./000.plan.md) dan `000b.plan-checklist.md`)
menghasilkan binary tunggal yang membuka port dengan PTY interaktif. README
menyorot containment path traversal, tetapi autentikasi belum disebut dan
belum diimplementasikan. Tanpa token atau password, siapa pun pada jaringan
yang sama dapat membuka shell di perangkat — di Termux pada hotspot publik
ini risiko nyata, bukan teoritis.

### 1.1 Fakta kode v0.1 yang menjadi titik awal

- Flag `--bind <ip>` dan `--lan` sudah ada (`src/config.rs:10,18` +
  `effective_bind()`); `--host` tidak perlu ditambahkan sebagai flag baru.
- Flag `--tls-cert` / `--tls-key` sudah ada di `Config` (`config.rs:22-26`)
  tetapi **belum di-wire**: tidak ada deps TLS server di `Cargo.toml` dan
  listener di `src/main.rs:47-58` selalu plain TCP. Milestone A harus
  "menghidupkan" flag yang sudah ada, bukan menambah flag baru.
- Doc comment `config.rs:16` mengklaim `--lan` "generates single-use
  pairing code", padahal **pairing belum diimplementasikan** — dokumen
  menjanjikan fitur yang tidak ada; klaim ini dikoreksi di Milestone A.
- Tidak ada endpoint `/api/v1/auth/*` di `create_router()`
  (`src/http.rs:57-70`).
- `SessionRegistry.take_output_rx()` (`src/session.rs:78`) adalah
  single-consumer: receiver diambil (take) oleh satu handler
  (`src/http.rs:197`). Reattach/multi-client membutuhkan perubahan
  arsitektur registry — bukan sekadar tambahan endpoint.
- `SessionRegistry.list_sessions()` (`src/session.rs:111`) sudah ada dan
  dapat dipakai UI, tetapi outputnya harus difilter dari secret.
- Regression traversal sudah ada sebagian sebagai unit test di
  `src/paths.rs` (`test_fs_002_path_traversal_defense`,
  `test_fs_003_symlink_containment`); suite saat ini hanya 8 test
  (boot 1, editor 1, term 2, paths 4) — sangat tipis.

### 1.2 Scope v0.2

1. **Auth + TLS** — dikerjakan pertama.
2. **Session persistence (detach/reattach)** — nama produk adalah Mux;
   menutup tab tidak boleh membunuh PTY.
3. **Test suite + CI** — regression test untuk seluruh traversal vector dan
   integration test WebSocket PTY, dijalankan pada matrix CI.
4. **(Opsional) upload/download file.**
5. **(Opsional) read-only share links.**

Item 4 dan 5 hanya dikerjakan bila scope wajib selesai lebih cepat dari
perkiraan.

## 3. Threat model

Milestone A dan B diukur terhadap model ancaman berikut:

| Attacker | Akses | Dilindungi oleh |
|---|---|---|
| Website jahat (dns-rebinding) | Bisa mengarahkan browser korban ke `127.0.0.1:7681` | Validasi exact `Origin` + pin `Host` terhadap bind address/port (`AUTH-006`, `SEC-003`); cookie `SameSite=Strict`; CSRF token |
| Perangkat lain di LAN | Dapat scan port, brute-force pairing | Pairing single-use, constant-time compare (`AUTH-003`), rate limit per-IP + global (`AUTH-004`), default bind loopback |
| Penyadap LAN (plain HTTP) | Dapat baca cookie/terminal | Warning eksplisit + README; TLS direkomendasikan (`LAN-006`); tanpa TLS, input/output terminal TIDAK dilindungi — tercatat sebagai batas |
| Malware lokal pada host | Akses proses/FS penuh | Di luar model (host = trust boundary). Catatan: token tidak pernah ditulis ke disk, hanya stdout saat startup |

Yang TIDAK dilindungi v0.2: multi-user, internet exposure, TLS publik
(Let's Encrypt), mTLS, OAuth. Semua eksplisit out-of-scope (lihat bagian 11).

## 4. Milestone A — Autentikasi + TLS

### A.1 Autentikasi dasar

- Server mencetak token bearer acak saat startup di mode local
  (bootstrap secret, single-use, CSPRNG minimal 32 byte, sesuai `AUTH-001`).
- Pertukaran token menjadi session cookie `HttpOnly`, `SameSite=Strict`,
  `Path=/`, dan `Secure` ketika TLS aktif; credential tidak disimpan di
  `localStorage` atau URL setelah pairing selesai (`AUTH-002`, `AUTH-011`).
- **Anti session-fixation**: id cookie dirotasi (session id baru) segera
  setelah pairing sukses, sebelum session digunakan (`AUTH-013`).
- Penolakan pairing dilakukan dalam constant time terhadap seluruh
  karakter token (`AUTH-003`).
- Session terikat ke client record, idle/absolute expiry, revocable;
  revocation langsung menutup seluruh WebSocket client (`AUTH-007`,
  `AUTH-008`, `AUTH-009`, `AUTH-010`).
- Secret tidak pernah muncul di log atau response (`AUTH-012`, `SEC-001`).
- **Regenerate**: `POST /api/v1/auth/regenerate` (dari Settings) dan
  signal/flag dari terminal host membuat bootstrap secret baru dan
  membatalkan pairing code yang belum dipakai (`AUTH-014`).

### A.2 TLS — wire-up flag yang sudah ada

- `--tls-cert <path> --tls-key <path>` benar-benar mengaktifkan HTTPS/WSS
  (saat ini flag diterima tetapi listener tetap plain TCP) (`LAN-006`).
- `--generate-cert` membuat self-signed certificate sementara di
  direktori data (`--data-dir`, default `~/.mux-web`) dengan permission
  0600, masa berlaku pendek (mis. 90 hari), dan warning yang jelas di
  output; sertifikat lama dibuang saat regenerate.
- Warning besar ditampilkan ketika bind non-loopback aktif tanpa TLS;
  warning kedua saat browser menerima self-signed cert.
- `--lan --tls-cert ... --tls-key ...` wajib didukung: HTTPS + WSS penuh
  pada mode LAN.

### A.3 Bind default dan mode eksplisit

- Bind default tetap `127.0.0.1` (`BOOT-001`); `--bind <ip>` dan `--lan`
  sudah ada dan tetap menjadi satu-satunya mekanisme (tidak menambah
  `--host`) (`BOOT-002`).
- Deteksi dan display IP private saat `--lan` (`LAN-002`) — saat ini belum
  diimplementasikan; output harus menampilkan seluruh alamat private yang
  valid dan mengabaikan loopback/link-local.
- Doc comment `config.rs:16` dikoreksi agar tidak mengklaim pairing yang
  belum ada.
- Endpoint `/api/v1/auth/clients` dan revoke tersedia di Settings
  (`AUTH-008`).

### A.4 Rate limit

- `POST /api/v1/auth/pair`: global 10 percobaan/menit dan per-IP 30/menit
  (default, dapat dikonfigurasi, lihat bagian 8). Melebihi limit → `429`
  + `Retry-After` (`AUTH-004`, `AUTH-010`).
- Rate limit juga berlaku pada WebSocket upgrade dan state-changing
  request; store dibatasi memori (fixed window, entries di-prune).
- Pairing code yang dipakai untuk brute-force di-regenerate otomatis
  setelah limit global tercapai.

### A.5 Token di URL bootstrap — keputusan eksplisit

URL `http://127.0.0.1:7681/<bootstrap-secret>` aman karena secret bersifat
single-use dan langsung ditukar menjadi cookie; sekalipun bocor dari
browser history, secret tidak dapat dipakai ulang. Konsekuensi diterima:
secret bisa muncul di history browser. Dilarang meletakkan secret pada
query string endpoint API selain endpoint pairing.

### A.6 Cookie di LAN plain HTTP

`Secure` flag TIDAK diaktifkan pada plain HTTP LAN (browser menolak cookie
tersebut), sehingga cookie dapat disadap di LAN tanpa TLS. Ini diterima
untuk trusted LAN saja dan selalu disertai warning; TLS wajib untuk
jaringan yang tidak dipercaya. Saat TLS aktif, gunakan prefix `__Host-`
pada nama cookie.

### A.7 README dan upgrade path

README harus menyebut auth secara eksplisit: token startup, cookie
session, TLS, dan default bind loopback — misal: "Every session is
authenticated; default bind is loopback-only." Bagian "Security &
Authentication" dengan tiga poin: token, TLS, loopback default.

**Breaking change**: v0.1 → v0.2 mewajibkan pairing untuk semua akses.
`update.sh` harus mencetak notice: setelah update, akses memerlukan token
yang dicetak saat `mux-web` dijalankan.

### A.8 Acceptance criteria Milestone A

- `AUTH-001..014`, `BOOT-001`, `BOOT-002`, `LAN-002`, `LAN-006`,
  `LAN-007`, `SEC-001`, `SEC-003` lulus di Linux; uji device Termux
  dijalankan bila perangkat tersedia.
- Default server tidak dapat diakses dari jaringan lain.
- Pairing brute-force dan replay ditolak; revoke langsung memutus WS.
- README menampilkan bagian "Security & Authentication".
- `update.sh` mencetak notice upgrade.

## 5. Milestone B — Session persistence (detach/reattach)

### B.1 Model attach — keputusan desain

**Satu client aktif per session** (single-attach). Ketika client baru
berhasil reattach, client lama menerima frame `0x04 ERROR` dengan pesan
"reattached elsewhere" lalu koneksinya ditutup. Model ini sederhana,
deterministik, dan mudah diuji; multi-attach (broadcast) ditunda
(lihat open questions, bagian 10).

### B.2 Perilaku

- Menutup tab / disconnect WebSocket tidak membunuh PTY; session tetap
  hidup selama grace period (`LIFE-004`).
- Session dapat di-dettach dari satu client dan di-reattach dari client
  lain (tab baru atau browser lain) selama masih hidup (`SESS-001`,
  `SESS-002`).
- Refresh halaman tidak menduplikasi reader/writer PTY (`LIFE-007`,
  `SESS-006`).
- UI menampilkan daftar session aktif (id, shell, umur, attach count,
  status client) dan tombol attach/detach per session (`SESS-003`).
- Idle session tanpa client diputus setelah grace period (`LIFE-005`,
  `SESS-004`). Grace period dimulai saat client terakhir disconnect;
  default 60 detik (`session_idle_timeout`, dapat dikonfigurasi).
- Batas jumlah session aktif tetap berlaku; session yang dilekatkan
  kembali dihitung dalam limit (`SESS-005`).
- Output memakai bounded channel; client lambat diputus dengan error yang
  jelas, bukan RAM yang tumbuh tanpa batas (lihat bagian 7 `000.plan.md`).
- **Terminal EXIT saat detached**: state session menjadi `closed` dengan
  exit code; reattach setelah exit menampilkan "session exited (code N)"
  tanpa menghidupkan ulang shell. Reconnect tidak pernah menghidupkan
  proses yang sudah mati.

### B.3 Buffer output saat detached — keputusan desain

PTY tetap berjalan tanpa client; writer task terus mengalirkan output ke
**ring buffer bounded** (default 256 KiB, `session_output_buffer`):
- Ring buffer menyimpan byte terbaru sejak client terakhir terputus.
- Reattach mengirim isi ring buffer terlebih dahulu, lalu live stream —
  client baru tidak melihat layar kosong sampai ada input berikutnya.
- Saat buffer penuh, byte tertua dibuang (drop-oldest); tidak ada
  alokasi tak terbatas (`SESS-007`).
- Resize client baru diteruskan ke PTY; ukuran PTY tetap ukuran terakhir
  saat detached.

### B.4 API

- `POST /api/v1/terminals` mengembalikan `session_id` yang bertahan dari
  pembuatan sampai terminasi (tidak berubah).
- `GET /api/v1/terminals` mendaftar session yang masih hidup beserta
  metadata (tanpa secret) — memakai `list_sessions()` yang sudah ada.
- `POST /api/v1/terminals/{id}/attach` (autentikasi cookie) → mengembalikan
  token WS single-use baru (TTL 10 detik, `ws_token_ttl`) + flag
  `replay_available`; memicu invalidasi attach client lama.
- `GET /api/v1/terminals/{id}/ws?token=...` menerima attach/reattach;
  token lama dianggap invalid setelah attach pertama.
- `DELETE /api/v1/terminals/{id}` tetap idempotent (`LIFE-003`).

### B.5 Acceptance criteria Milestone B

- Test integration: connect → disconnect → reconnect dalam grace period
  → output berlanjut tanpa duplikasi, dengan replay ring buffer.
- Test: detach dari client A, attach dari client B → A menerima frame
  ERROR "reattached elsewhere"; B mendapat satu stream yang sama
  (`SESS-008`).
- Test: dua attach bersamaan → tepat satu yang menang, loser error.
- Test: exit saat detached → reattach menampilkan status exited.
- `SESS-001..008`, `LIFE-004`, `LIFE-005`, `LIFE-007` lulus.
- Tidak ada child process yatim setelah semua jalur close (regression
  `LIFE-002`).

## 6. Milestone C — Test suite + CI

### C.1 Regression traversal — matrix lengkap

Perluas unit test yang sudah ada di `src/paths.rs` menjadi matrix
terstruktur (test per baris, unit + integration pada endpoint file):

| Vektor | Contoh | Expected |
|---|---|---|
| `..` | `a/../b` | tolak |
| Encoded slash | `a%2Fb` | tolak |
| Double encode | `%252e%252e` | tolak |
| Overlong UTF-8 | `%c0%ae%c0%ae` | tolak (decode ketat, sekali) |
| Fullwidth slash | `%ef%bc%8f` | tolak |
| Backslash | `%5c` | tolak (defense in depth) |
| NUL | `%00` | tolak sebelum canonicalize |
| Absolute | `/etc/passwd` | tolak |
| Symlink escape | `root/link -> /etc` | tolak; symlink antar-root ditampilkan sebagai symlink |
| Hardlink | `root/hard -> inode di luar root` | tolak bila sistem file mendukung (`FS-016`) |
| TOCTOU symlink | swap direktori saat validasi | tolak via `O_NOFOLLOW` + re-verify berbasis fd (`FS-004` diperluas) |
| TOCTOU rename | rename target setelah validasi, sebelum open | tolak/aman dengan re-verify |
| Path murni | trailing dots `a..`, `a.` | perilaku didefinisikan (normalisasi) |

Aturan `root_id + relative_path` selalu dicanonicalize dua kali: target
dan parent, untuk move/copy lintas root (`FS-014`).

### C.2 Integration WebSocket PTY

- Codec frame biner valid/invalid (`TERM-001`, `TERM-002`); malformed
  frame tidak pernah menghentikan session lain.
- Spawn shell, input/output/resize, exit, close (`TERM-003`..`TERM-009`).
- Oversized frame/paste ditolak (`TERM-011`), bounded backpressure
  (`TERM-012`), control sequence tidak disuntikkan ke DOM (`TERM-010`).
- Cleanup process group setelah close/shutdown (`LIFE-001`, `LIFE-002`).
- **Harness**: test integration memakai port ephemeral (bind `127.0.0.1:0`
  per test, paralel aman); dev-dependencies: `reqwest` (sudah ada,
  rustls-tls) untuk HTTP + `tokio-tungstenite` untuk WS; file baru:
  `tests/auth_tests.rs`, `tests/session_tests.rs`, `tests/fs_tests.rs`.

### C.3 CI GitHub Actions

- **CI-001** — Build & test: matrix `x86_64-unknown-linux-gnu`
  (ubuntu-latest, `cargo test`) + cross-compile check
  `aarch64-linux-android` (rustup target + NDK versi dipin; `cargo-ndk`);
  smoke test Termux nyata bila runner/device tersedia (label
  `self-hosted-termux`).
- **CI-002** — Traversal regression suite (C.1) pada kedua target yang
  dapat dijalankan.
- **CI-003** — WS PTY integration (C.2).
- **CI-004** — Budget gate: `scripts/check_budget.sh` + laporan
  size/RSS sebagai artifact (`PERF-001..003`).
- **CI-005** — Release artifact: upload binary + checksum pada tag
  `v0.2.*` (SBOM opsional, dijanjikan di `000.plan.md` M5).
- **CI-006** — Frontend: `npm ci`, typecheck, vitest, `vite build`,
  cek bundle gzip <= 750 KiB (`PERF-002`).
- **CI-007** — Kualitas: `cargo fmt --check`, `clippy -D warnings`,
  `cargo audit` (deny high severity). Untuk rilis security, audit
  dependency bukan opsional.
- Cache cargo per target; `pull_request` + `push main` untuk CI-001..004,
  006, 007; CI-005 hanya saat tag.
- Flaky test diperlakukan sebagai bug (aturan `000a.plan-test.md`); retry
  hanya alat diagnosis, bukan hasil pass resmi.
- Coverage: laporan `cargo llvm-cov` di-upload sebagai artifact tanpa
  ambang wajib di v0.2 (diputuskan eksplisit, bukan dilupakan).

### C.4 Acceptance criteria Milestone C

- Seluruh traversal vector regression lulus di CI matrix.
- Integration WS PTY lulus di Linux x86_64 dan ARM64.
- Budget gate hijau dan artifact ter-upload saat tag.
- `cargo audit` bersih (tanpa high severity).

## 9. Kontrak API v0.2

Status code umum: `401` (belum terautentikasi), `403` (CSRF/Origin/Host
ditolak), `404` (session/root tidak ada), `409` (konflik, mis. attach
ganda), `429` (rate limit), `413` (body terlalu besar). Envelope error
konsisten:

```json
{"error": {"code": "AUTH_REQUIRED", "message": "pairing required"}}
```

- `POST /api/v1/auth/pair` — body `{"secret": "..."}`; sukses: `200`,
  set cookie (dirotasi setelah sukses, `AUTH-013`); gagal: `401` (constant
  time), `429` + `Retry-After`.
- `POST /api/v1/auth/logout` — `204`; revoke session + tutup WS miliknya
  (`AUTH-009`).
- `GET /api/v1/auth/clients` — `[{id, created_at, last_seen, remote_ip}]`
  tanpa secret (`AUTH-008`).
- `DELETE /api/v1/auth/clients/{id}` — `204`; langsung putus WS
  (`AUTH-010`).
- `POST /api/v1/auth/regenerate` — `200 {"bootstrap": "<secret>"}`;
  membatalkan pairing pending (`AUTH-014`).
- `GET /api/v1/terminals` — `{"sessions": [{id, shell, state, created_at,
  idle_since, attach_count, has_client}]}`.
- `POST /api/v1/terminals/{id}/attach` — `200 {"ws_token": "...",
  "replay_available": true}`; `409` bila session `closed`.
- `GET /api/v1/terminals/{id}/ws?token=...` — upgrade WS; token single-use
  TTL 10 s; attach baru mengirim `0x04 ERROR "reattached elsewhere"` ke
  client lama (B.1).

## 10. Keputusan desain dan open questions

Keputusan (sudah ditetapkan v0.2):
- Single-attach per session; reattach menggantikan client lama (B.1).
- Ring buffer drop-oldest untuk output detached (B.3).
- Grace period dihitung sejak client terakhir terputus (B.2).
- Token WS single-use per attach, TTL 10 s (B.4).
- Rotasi cookie setelah pairing (A.1, AUTH-013).

Open questions (diputuskan saat implementasi, dicatat di checklist 001b):
- Multi-attach broadcast untuk viewer read-only — ditunda, bukan bagian
  v0.2.
- Reattach dari device yang berbeda dengan cookie expired: apakah session
  dibiarkan hidup menunggu pairing baru? (rekomendasi: ya, PTY tetap
  hidup; UI menampilkan "re-pair untuk attach").
- Perilaku detach eksplisit dari UI vs implisit close tab — apakah perlu
  tombol "detach" terpisah (rekomendasi: ya, setara close window tanpa
  terminasi).

## 13. Risiko Termux/Android untuk auth

- Browser Android tidak mempercayai self-signed cert: pengguna harus
  menerima warning manual — dokumentasikan di README; uji di device.
- Android dapat membunuh server saat background → pairing harus bisa
  diulang dengan mudah (token baru dicetak saat restart).
- `~/.mux-web` (data cert) harus di private storage Termux, bukan shared
  storage (mengikuti aturan `000.plan.md` §4).
- Layout keyboard Android + pairing: URL token panjang harus dapat
  disalin; `termux-open-url` tetap convenience-only.
