## 1. Latar Belakang & Risiko

### 1.1 Laporan Bug (verbatim ringkas)

Project aktif di editor: `[HOME]/printing-web-app` (memiliki `.git`).
Terminal editor → `pwd` = `/data/data/com.termux/files/home` (salah, seharusnya
`/…/home/printing-web-app`). Akibat: `git status` → `fatal: not in a git directory` (2×).
Header terminal menampilkan `bash — home:/printing-web-app` tetapi `pwd` berbeda
(inkonsistensi UI). Prompt menampilkan kotak/karakter rusak (ANSI/Unicode tidak ter-render).

Screenshot (2026-08-22) mengkonfirmasi keempat gejala di atas — lihat `spec/specs/007` issue image.

### 1.2 Kondisi Saat Ini (fakta kode — titik awal)

UI pada screenshot sudah menampilkan fitur 006 (header `bash — home:/printing-web-app`,
chip status bar `[HOME] /printing-web-app` + `⎇ main`), sehingga **frontend baru sudah
ter-deploy**, tetapi `pwd` masih `$HOME`. Artinya **frontend dan backend tidak sinkron
versi** atau respons backend tidak memberi bukti cwd yang dipakai.

### 1.3 Root-Cause Analysis

| RC | Akar Masalah | Mekanisme Gagal | Gejala |
|---|---|---|---|
| RC-01 | **Version skew diam-diam** — binary backend lama di perangkat mengabaikan field `cwd_root/cwd_path` (serde `default` → `None` → fallback `config.work_dir = $HOME`) sementara frontend baru mengirimnya | User update frontend (`dist/index-*.js`) tanpa update binary, atau `install.sh` tidak rebuild backend | `pwd` = `$HOME` padahal header `home:/printing-web-app` |
| RC-02 | **Tidak ada bukti server-authoritative di respons** — `POST /api/v1/terminals` mengembalikan `SessionMetadata` tanpa `work_dir` | Frontend hanya bisa menebak label dari `ws` lokal; tidak ada cara membuktikan `chdir` berhasil | Inkonsistensi header ≠ `pwd` tidak terdeteksi |
| RC-03 | **Tidak ada handshake versi di boot** — frontend tidak memeriksa `health.version` | Skew RC-01 tidak pernah di-warning | Bug terlihat seperti "fitur rusak" padahal deploy salah |
| RC-04 | **Font tidak mencakup PUA glyph** — `TerminalView` font stack tanpa Nerd Font + tanpa `unicode11` addon | Prompt Termux (starship/p10k/oh-my-zsh powerline) emit U+E0B0..U+EBxx PUA | Kotak berwarna / karakter aneh di prompt |

## 3. Threat Model

| Skenario | Vektor | Pertahanan Wajib |
|---|---|---|
| **cwd traversal** | `POST /terminals {"cwd_root":"home","cwd_path":"../../etc"}` | Tetap `AllowedRoots::resolve_path` (`src/paths.rs:64-151`) sebelum `work_dir`; gagal → `400 PATH_TRAVERSAL` (RC-01 tidak boleh bypass) |
| **NUL / encoding** | `"a\0b"`, overlong UTF-8 | Ditolak resolver (`NulByteDetected`, `InvalidUtf8`) — sama seperti 006 |
| **Path leak di UI** | `work_dir` absolute bocor | Header menampilkan **relative** `rootId:relative` (pola 006); absolute hanya untuk debug `title` attribute — bukan default visible |
| **Nerd Font supply chain** | woff2 dari upstream tidak terverifikasi | Font diambil dari rilis resmi Nerd Fonts (`JetBrainsMono Nerd Font Mono`), subset di-embed, checksum dicatat di spec; tidak ada fetch runtime |
| **Version spoof** | `health.version` dipalsukan | `health` adalah `env!("CARGO_PKG_VERSION")` compile-time, bukan dari request; tidak dapat di-spoof via header |
| **DoS via skew banner** | Banner warning di-spam | Banner muncul sekali per session, dismissible, tidak memblokir editor |

Yang **tidak** dilindungi 007: autentikasi baru, perubahan `AllowedRoots`, perubahan lifecycle PTY (`LIFE-005`), plugin/remote internet.

## 4. Milestone A — Backend: `work_dir` di Respons + Versi `0.5.1` (`V051-001`, `V051-005`)

### 4.1 Perilaku Target

1. `POST /api/v1/terminals {"cwd_root":"home","cwd_path":"/printing-web-app"}` → `201`
   body memuat `work_dir` absolute yang dipakai (mis. `/data/data/com.termux/files/home/printing-web-app`).
2. Request tanpa `cwd_*` atau `cwd_path=""` → `work_dir = config.work_dir` (kompatibel lama).
3. `cwd_path` traversal/NUL → `400 PATH_TRAVERSAL`, **tidak ada** PTY dibuat.
4. `GET /api/v1/health` → `{"status":"ok","version":"0.5.1"}` setelah bump versi.

### 4.2 Keputusan Desain

* **Additive field pada metadata**, bukan endpoint baru. Opsi A (resp body) vs B (header `X-Work-Dir`) —
  pilih A karena konsisten dengan `SessionMetadata` JSON dan mudah di-test. Field `work_dir:
  Option<String>` dengan `skip_serializing_if = Option::is_none` agar payload lama identik
  bila `None` (tidak ada perubahan wire untuk klien lama).
* Struktur respons create: perluas struct yang di-serialisasi oleh `create_terminal_handler`
  (`src/http.rs:592 Json(meta)`). `meta` saat ini `SessionMetadata` (`src/session.rs:22`);
  tambah `work_dir: Option<PathBuf>` yang diisi dari `work_dir` yang sudah di-resolve.
  Serialisasi `PathBuf` → string absolute.
* Bump versi: ubah `Cargo.toml:3 version = "0.5.1"` dan `web/package.json:4 version = "0.5.1"`.
  Tidak ada env flag baru. `health.version` otomatis ikut karena `env!("CARGO_PKG_VERSION")`.

### 4.3 Acceptance Milestone A

- [ ] `POST /terminals {cwd_root:"home",cwd_path:"/sub"}` → `201` dan `body.work_dir` berakhiran `/sub`.
- [ ] Variasi stabil: `cwd_path:""` / tidak ada field → `work_dir` = `config.work_dir`.
- [ ] `POST {cwd_path:"../.."}` → `400` `PATH_TRAVERSAL`, tidak ada session bertambah (regresi 006 tetap).
- [ ] `GET /health` → `version:"0.5.1"` (setelah bump).
- [ ] `cargo test --test session_tests` termasuk test baru A tetap hijau; `clippy -D warnings` 0.

## 5. Milestone B — Frontend: Header = Server `work_dir` + Version Gate (`V051-002`, `V051-003`)

### 5.1 Perilaku Target

1. **Header terminal** `TextEditorView.tsx:720` tidak lagi menebak dari `ws` saja.
   Setelah `POST /terminals` sukses, header menampilkan `work_dir` dari respons
   (`meta.work_dir`) sebagai `rootId:relative` (dihitung via `ws` → relative). Bila
   respons tidak punya `work_dir` (server lama) → fallback ke `ws` lama + tampilkan
   banner kuning: `⚠️ Server lama — update untuk cwd yang benar`.
2. **Boot version gate**: saat `TextEditorView` mount, `fetch /api/v1/health` sekali.
   Bila `version < 0.5.1` (semver compare sederhana, `0.5.1` adalah minimum) → banner
   merah dismissible di atas editor: `Server vX.Y.Z — butuh ≥0.5.1 untuk terminal cwd. Jalankan update.sh / reinstall.`
   Chip versi di status bar / taskbar menampilkan `vX.Y.Z` (hijau bila ≥0.5.1, merah bila <).
3. Tidak ada auto-`pwd` injection ke PTY (mengotori shell history). Verifikasi cwd
   dilakukan via respons, bukan via mengetik di shell.

### 5.2 Keputusan Desain

* **Reuse `health`**, tidak menambah route. `host_origin_middleware` sudah exempt
  `/api/v1/health` — tidak ada perubahan auth.
* Parsing `work_dir` absolute → relative untuk label: cari `allowedRoots` entry yang
  prefix-nya cocok (atau simpler: tampilkan basename + full path di `title` attribute).
  MVP: bila `work_dir` ada, label = `bash — ${work_dirBasename}` + `title={work_dir}`;
  fallback tetap `home:/printing-web-app` bila tidak ada mapping. Tidak perlu menambah
  `AllowedRoots` reverse lookup baru di frontend bila rumit.
* Banner: komponen kecil di atas split panel, `role="alert"`, dismiss dengan `×`, tidak
  memblokir input editor/terminal.
* Polling health tidak perlu — cukup sekali saat mount + saat `spawnTerminal` bila
  sebelumnya gagal (retry).

### 5.3 Acceptance Milestone B

- [ ] Mock `POST /terminals` → `{id:"t1", work_dir:"/home/u/printing-web-app"}` → header
      menampilkan path tersebut (bukan tebakan), `title` attribute = absolute.
- [ ] Mock server lama (tanpa `work_dir` di respons) → header fallback + banner kuning muncul.
- [ ] `GET /health` mock `0.3.0` → banner merah + chip merah `v0.3.0`; mock `0.5.1` → tidak ada banner.
- [ ] Fetch health gagal (offline) → degrade ke warning ringan, tidak crash.
- [ ] `vitest` editorLogic + TextEditorView logic terkait hijau.

## 6. Milestone C — Prompt Rendering Tanpa Kotak Rusak (`V051-004`)

### 6.1 Perilaku Target

Prompt shell yang memakai powerline/nerd glyph (mis. ``, ``, ``) di Termux
(starship, p10k, oh-my-zsh) tampil **tanpa kotak tofu** di `TerminalView` baik di
editor split maupun window terminal terpisah. `pwd` dan `git status` tetap terbaca.

Screenshot before/after: before = kotak berwarna (issue image); after = segmen panah
dan ikon git tampil utuh pada `JetBrainsMono Nerd Font`.

### 6.2 Keputusan Desain

* **Font**: bundle subset **JetBrainsMono Nerd Font Mono** `woff2` (hanya PUA
  U+E000–U+EBFF + Box Drawing) ke `web/public/fonts/` atau `web/src/assets/fonts/`,
  `@font-face` di `web/src/styles/main.css` atau `TerminalView.css`, `font-display: swap`.
  `TerminalView.tsx:24` `fontFamily` menjadi
  `"'JetBrainsMono Nerd Font Mono','JetBrains Mono','Fira Code',monospace"`.
  Budget: subset ~30–80 KiB woff2 (gzip ~20–50 KiB).
* **Unicode**: tambah `npm: @xterm/addon-unicode11 ^0.8.0`, `term.loadAddon(new Unicode11Addon())`
  + `term.unicode.activeVersion = '11'` untuk wide char & combining yang benar.
  Tidak mengubah `convertEol` atau `rendererType` (tetap canvas).
* Alternatif yang ditolak: memaksa `PS1` plain di server (merusak ekspektasi user),
  CDN font (offline Termux gagal), bitmap fallback (buram).

### 6.3 Acceptance Milestone C

- [ ] `TerminalView` render string uji `"\uE0B0 \uE0B1 \uE0B2 "` tanpa kotak (visual / snapshot test
      atau manual E2E: paste glyph, tidak ada `�`).
- [ ] `unicode11` addon ter-load (mock: `term.unicode.activeVersion === '11'`).
- [ ] `npm run build` gzip tetap **≤750 KiB** (sekarang ~98 KiB → +font masih ≤150 KiB).
- [ ] Tidak ada regresi `FitAddon` / resize 75ms RSZ-006; drag split tetap 60fps.
