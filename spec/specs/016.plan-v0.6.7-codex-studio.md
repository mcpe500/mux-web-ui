## 1. Latar Belakang & Fakta Kode

### 1.1 Permintaan user

UI Codex yang "indah & ringan", setara 1:1 dengan kemampuan Codex CLI:
percakapan berkelanjutan (bukan one-shot), custom model/API/API key, login
mudah, **tags, agents (subagents), skills, MCP**, web search, gambar — tanpa
kehilangan keamanan existing (denylist flag, argv-only, satu PTY).

### 1.2 Kondisi saat ini (fakta kode — titik awal)

| Fakta | Lokasi |
|---|---|
| Codex window = ONE PTY, dual surface chat/terminal | `web/src/apps/agent/AgentCodexView.tsx` |
| Peluncuran = ketik `codex exec --json "<prompt>"` ke shell PTY | `codexBridge.composeLaunchInput` |
| Mapper JSONL v1/v2 → 5 event kanonik + drift detector | `codexEvents.ts`, `transcriptBuffer.ts` |
| Riwayat sesi = in-memory ring 20, events kosong, hilang saat refresh | `codexBridge.HistorySession` |

| Config editor codex (Route via 9Router) | `agent_cfg.rs`, Support Hub (spec 013) |

### 1.3 Kemampuan Codex CLI terkini (verifikasi docs resmi, INV-01)

- Multi-turn headless: `codex exec resume <SESSION_ID> --json "<prompt>"`
  (sesi tersimpan di `~/.codex/sessions/`); event `thread.started` membawa
  `thread_id`; akhir turn = `turn.completed` / `turn.failed`.
- Auth: ChatGPT OAuth **atau** API key (`OPENAI_API_KEY`).
- Custom provider: `model_providers.<id>` (name, base_url, env_key, wire_api)
  + `model_provider` + `model` di `~/.codex/config.toml`; profiles
  `$CODEX_HOME/<nama>.config.toml` via `--profile`.
- MCP: `mcp_servers` (config global / per-agent); `codex mcp`.
- Skills: folder `SKILL.md` di `~/.codex/skills` & `.codex/skills`; invoke
  `$skill`; enable/disable via `[[skills.config]]`; `$skill-installer`.
- Subagents: `.codex/agents/<nama>.toml` (model, sandbox_mode,
  developer_instructions, mcp_servers); panel `/agent`.
- Lainnya: `--search` (web), `--image`, approval_policy/sandbox (`/permissions`),
  `codex cloud`, plugins.

### 1.4 Risiko tanpa desain

1. Composer mengirim teks mentah saat codex tidak berjalan → shell mengeksekusi
   teks user sebagai perintah (perilaku membingungkan/berbahaya).
2. Riwayat hilang saat refresh → konteks kerja hilang.
3. Chat polos tanpa markdown/diff → UX jauh di bawah CLI/IDE resmi.

## 2. Threat Model (lanjutan §10 spec 011 + §2 spec 014)

- **T1 thread-id injection**: threadId dari event JSONL dipakai menyusun baris
  resume yang DIKETIK ke shell → wajib allowlist ketat `^[A-Za-z0-9_-]{1,64}$`
  (unit test: id dengan `;`, `$(`, spasi, >64 char ditolak).
- **T2 XSS via transcript**: assistant text dirender markdown → `markdownLite`
  WAJIB escape semua HTML sebelum transformasi; unit test: `<script>`,
  `<img onerror>`, `javascript:` link tidak lolos.
- **T3 secret leakage**: milestone C — API key tidak pernah dikirim balik ke
  klien/log; ditulis ke `auth.json`/env dengan mode 0600 (denylist audit).
- **T4 denylist regression**: `--search`/resume tetap wajib lolos
  `validateCodexOpts`; prompt tak pernah shell-joined (argv→quote→type).
- **T5 storage poisoning**: sessionStore toleran JSON korup (heal seperti
  promptLibrary), cap ketat (30 sesi × 300 event) anti-quota.

## 3. Milestone A — Session Engine (`CDX-001..006`)

- **CDX-001** Penangkap thread id: `extractCodexThreadId(line)` pure — kenal
  `thread.started` (thread_id), `session.created`/legacy `session_id`,
  `thread.resumed`. Toleran (null bila tidak ada).
- **CDX-002** Sinyal akhir turn: `isTurnEndLine(line)` — `turn.completed`,
  `turn.failed`; classifier mengenali keduanya + `thread.*`/`session.*` sebagai
  recognized (menurunkan drift false-positive).
- **CDX-003** `OutputPump`/`TranscriptAccumulator` memperlihatkan
  `threadId()` + `drainTurnEnded(): boolean` tanpa mengubah kontrak push().
- **CDX-004** `sessionStore.ts`: persistence localStorage per-workspace
  (pola promptLibrary): `CodexSessionRecord{id, threadId, title, tags[], envId,
  model?, sandbox?, startedAt, lastActiveAt, status, transcript[]}`; API
  list/save/remove/setTags/search; cap 30 sesi × 300 event; toleran korup.
- **CDX-005** `buildCodexResumeArgs` di `codexArgs.ts` (+validasi threadId & opsi
  `--search` untuk exec baru) — argv-only, tanpa shell-join.
- **CDX-006** Mesin turn di komponen: state `running|idle`; saat idle + ada
  threadId → kirim = ketik baris resume (bukan teks mentah); saat running →
  raw keys (approval/mid-run); autosave transcript (debounce + on turn end).

## 4. Milestone B — Studio UI (`CDX-010..016`)

- **CDX-010** `markdownLite.ts`: escape-first markdown → HTML (heading 1-3,
  bold/italic, inline code, fenced code, bullet/numbered list, link http/https
  saja). Tanpa dependensi baru (ringan).
- **CDX-011** Chat redesign: assistant = markdown + kartu; user = bubble kanan;
  tool_call = kartu collapsible (name + args preview); tool_result = collapsible
  redup; error = banner merah. Render cap 300 event tetap.
- **CDX-012** Session browser di launcher: search box, filter tag (chips), daftar
  sesi (judul, thread id pendek, badge tag, status dot, last active), aksi
  Lanjutkan/Hapus; tag editor inline (tambah/hapus chip).
- **CDX-013** Header live: badge thread id, indikator turn (running/idle),
  jumlah event; tombol kembali launcher mempertahankan sesi (bukan reset).
- **CDX-014** Composer: saat idle menampilkan hint "↵ mulai turn baru (resume)";
  multiline tetap ditolak di jalur ketik (documented limitation).
- **CDX-015** Toggle web search (`--search`) di peluncur (default off, gaya
  checkbox "🌐 Web search").
- **CDX-016** Resume lintas-refresh: buka sesi dari browser → PTY baru dibuat
  saat kirim pertama; transcript dipulihkan dari sessionStore; exec baru =
  `codex exec resume <id>`.
