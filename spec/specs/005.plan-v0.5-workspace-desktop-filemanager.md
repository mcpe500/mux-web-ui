## 1. Latar Belakang dan Risiko

**v0.4** sudah memberi Git UI (tapi `rootId='home'` hardcode `web/src/apps/git/GitView.tsx:8`), Package Center, Share, Archive — semuanya butuh `?root=&path=` yang datang dari File Explorer. Masalahnya:

1. **Tidak ada Workspace** — File Explorer punya dropdown `home/cwd` `web/src/apps/files/FileExplorerView.tsx:92`, tapi pilihan itu hilang saat reload, tidak dipakai Git/Terminal/Archive, dan tidak mendukung multi-folder project (mis. `~/work/frontend` + `~/work/backend`).
2. **Tidak ada Desktop System** — `DesktopCanvas.tsx:12` hanya `windowReducer` + taskbar, belum ada **icon di desktop**, **wallpaper**, **snap/grid**, **widget layer**, **start menu** search. Window layout disimpan di `localStorage` parsial (`WIN-006`) tapi tidak terikat workspace.
3. **File Manager belum lengkap** — `000.plan.md:§3 MVP` janji *create/rename/copy/move/trash/search/properties* tapi yang ada sekarang `FileExplorerView.tsx:24` hanya `list`, `Terminal Here`, breadcrumb manual. Belum ada: copy/move dengan progress, trash (bukan delete permanen), search scoped, drag-drop, preview, `Open in Git/Package/Archive/Share`.

Tanpa ketiganya, alur `File Manager → Git → Terminal` terputus.

### 1.1 Fakta Kode v0.4 sebagai Titik Awal

- **AllowedRoots `src/paths.rs:45`** — `home` + `cwd` kanonikalisasi + tolak `..`/symlink. Workspace wajib reuse ini, tidak boleh nambah path bebas.
- **FileExplorerView `src/apps/files/FileExplorerView.tsx:24`** — sudah `fetch /api/v1/fs/roots` + `GET /api/v1/fs/entries?root=&path=`. Kurangnya: `POST /api/v1/fs/actions` belum terhubung ke UI (copy/move/trash).
- **Desktop `web/src/desktop/DesktopCanvas.tsx:12` + `windowStore.ts:1`** — `WindowState {appId, x, y, w, h, zIndex}` + `windowReducer` tile/grid. Belum ada `desktopIcons: {path, x, y}[]` atau `workspaces: {id, name, roots, layout}[]`.
- **Git `src/git.rs:21` + `src/http.rs:1133`** — no-shell `Command`, tapi belum ada `discover` atau `workspace` endpoint. `GitView.tsx:8` perlu picker.
- **Persistence `localStorage` `WIN-006`** — sudah dipakai layout, belum untuk workspace.

## 3. Threat Model

| Skenario | Vektor | Pertahanan |
|---|---|---|
| **Workspace path escape** | `PUT /workspaces` kirim `{"root":"home","path":"../../etc"}` | `AllowedRoots::resolve_path` `src/paths.rs:63` + tolak `..`/`NUL` |
| **Desktop icon traversal** | Icon `path` `../../../../.ssh/id_rsa` | Sama — icon hanya boleh `rootId+relative` di AllowedRoots |
| **File action injection** | `POST /api/v1/fs/actions` `copy {src: "a; rm -rf"}` | Schema bertipe `FsAction` `src/files.rs`, tidak ada `sh -c` |
| **Search DoS** | `q=a*` scan seluruh `home` | Bound `max_results=100`, `max_depth=5`, `q` min 2 char regex `^[a-zA-Z0-9+._-]*$` reuse `PKG-005` |
| **Workspace flooding** | Buat 1000 workspace | Limit `max_workspaces=20`, `max_icons=100` |

## 4. Milestone A — Workspace System (`WS-001..006`)

**A.1 Konsep (perlu keputusan user — lihat §9.1):**
- **Opsi A (Single-folder workspace, simple):** 1 workspace = 1 dealias `rootId+path` (mis. `home:/work/app`). Cocok Termux (biasanya 1 project).
- **Opsi B (Multi-root VS Code style):** 1 workspace = N entry `[{rootId,path}]` (mis. `frontend` + `backend`). Lebih powerful tapi UI picker lebih kompleks.

> Rekomendasi awal: **A dulu, B di `v0.5.1`** — biar File Manager & Git langsung pakai.

**A.2 API:**
- `GET /api/v1/workspaces` → `[{id,name,root,path,created_ms}]`
- `POST /api/v1/workspaces` `{name, root, path}` → `201` (validasi `AllowedRoots`)
- `PUT /api/v1/workspaces/current` `{id}` → set aktif (also `localStorage["mux_workspace_current"]`)
- `GET /api/v1/workspaces/current` → workspace aktif
- `GET /api/v1/git/repos?root=&path=&depth=5&limit=50` → discover repo (reuse `sanitize` `src/archive.rs:63`)

**A.3 Frontend:**
- `WorkspaceSelector.tsx` di top-bar FileExplorer + GitView: dropdown `Recent Workspaces` + `[Set as Workspace]` (persist `localStorage` + `PUT`).
- `DesktopCanvas` baca `currentWorkspace` untuk default `openGit/openTerminal/openFileExplorer`.

### Acceptance:
- [ ] `WS-001` `POST /workspaces` tolak `../` → 400.
- [ ] `WS-002` `GET /current` setelah `PUT` mengembalikan workspace benar (persist reload).
- [ ] `WS-003` FileExplorer `Set Workspace` update GitView tanpa reload.

## 6b. Milestone E — Browser App Inside Desktop (`BR-001..004`)

Browser di dalam Mux Desktop (bukan browser luar) untuk preview docs, `localhost` app, atau internet (jika diizinkan). Pakai **iframe sandboxed** — tidak butuh backend proxy untuk MVP.

| ID | Fitur | UI |
|---|---|---|
| `BR-001` | **Iframe sandboxed** | `web/src/apps/browser/BrowserView.tsx` `<iframe sandbox="allow-scripts allow-same-origin" src={url}>` |
| `BR-002` | **Tabs** | `TabData` reuse editor pattern, `+` new tab |

| `BR-004` | **Bookmarks + History** | `localStorage["mux_bookmarks"]`, `localStorage["mux_history"]` limit 100 |

Security: iframe `sandbox` tanpa `allow-top-navigation` isolasi. Tidak bypass CSP `src/http.rs:361`. Untuk `localhost:3000` dev server, user bisa browse via `http://127.0.0.1:3000` jika `lan` + port diizinkan.

### Acceptance:

## 9. Pertanyaan Diskusi untuk User (Sebelum Build)

**Pilih sebelum implementasi:**
1. **Workspace model** — mau **Single-folder (A)** dulu atau langsung **Multi-root (B)** seperti VS Code (`frontend`+`backend` dalam 1 workspace)?
2. **Persist di mana** — cukup **`localStorage`** (per-browser, simple) atau perlu **server file** `~/.mux-web/workspaces.json` biar sinkron Termux↔Linux?
3. **Desktop icon** — mau **icon di desktop** (file/folder shortcut) atau cukup **file manager window** saja dulu? Kalau icon, mau **drag-drop dari file manager ke desktop**?
4. **Widget** — `GitWidget` mau di **taskbar** (seperti Monitor mini) atau **desktop widget** pinned? Atau keduanya?
5. **File Manager prioritas** — dari `FM-001..010` mana yang paling urgent menurut kamu: **Copy/Move+Trash**, **Search**, atau **Preview**?

> Jawab 1-5 singkat (mis. `A, localStorage, icon ya, taskbar, Copy+Search`) nanti saya langsung jadikan `Status: approved` + checklist `005b` dan eksekusi TDD.
