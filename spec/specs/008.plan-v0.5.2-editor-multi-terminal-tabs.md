## 1. Latar Belakang & Risiko

### 1.1 Kondisi Saat Ini

| Fakta | Lokasi | Catatan |
|---|---|---|
| Editor = **tepat 1** terminal | `web/src/apps/editor/TextEditorView.tsx` (state `termId/showTerminal`) | EDT-001 sengaja no-duplicate; multi tunda ke "v0.7" (spec 006 §8 poin 1) |
| Limit global PTY konstanta | `src/session.rs:53` `MAX_SESSIONS: usize = 4`; dipakai `create_session` `:167` | Tidak bisa dikonfigurasi; spec 000 §12 justru minta *dapat dikonfigurasi sampai batas aman* |
| `SessionConfig {grace_period, output_buffer, ws_token_ttl}` | `src/session.rs:37` | Tempat alami menambah `max_sessions` |
| Wiring produksi | `src/main.rs:124` `SessionRegistry::new_with(SessionConfig{..})` | Titik tempel flag baru |
| Metrics tanpa info limit | `src/http.rs:62` `MetricsResp {active_terminals, allowed_roots_count, uptime_seconds}` | UI butuh `max_sessions` untuk guard "N/max" |
| TerminalView per-session | `web/src/apps/terminal/TerminalView.tsx:10` — attach WS + fit + exit overlay | Instance terpisah per tab; hidden CSS tetap konek → scrollback terjaga |
| Guard MAX_SESSIONS sudah ramah | `editorLogic.ts spawnErrorMessage(409)` | Reuse untuk multi-tab |

Risiko utama tanpa desain: spam tab menghabiskan kuota global PTY sehingga app Terminal
terpisah tidak bisa buat session; xterm tersembunyi harus tetap re-fit saat ditampilkan.

### 1.2 Prinsip Desain

VS Code parity yang **diterapkan**: tab strip navigasi, `+` terminal baru, split ke grup
kanan (side-by-side), drag & drop tab antar/within grup, divider antar-grup draggable,
close per-tab, restart per-tab, panel resize vertikal (sudah ada, dipertahankan).
Yang **tidak** diterapkan (lihat §9): rename tab manual, shell profile per-tab, terminal
di area editor atas, grid 2×2.

## 3. Threat Model

| Skenario | Vektor | Pertahanan Wajib |
|---|---|---|
| **PTY exhaustion DoS** | Spam `+` hingga kuota global habis | Backend tetap satu-satunya gate (`max_sessions`); frontend disable tombol saat spawning + pesan 409 ramah; nilai flag clamp 1..=16 agar low-end aman |
| **Zombie PTY** | Tutup tab/group/panel sembarangan | Setiap remove tab wajib `DELETE /terminals/{id}` (idempotent, LIFE-002 janitor tetap backstop) |
| **Scrollback leak RAM** | Banyak instance xterm hidup | Ring buffer server tetap bounded per-session; client-side hanya metadata ringan; jumlah tab dibatasi kuota global |
| **Drag-drop injection** | dataTransfer dimanipulasi | Hanya key internal tab yang dikirim; validasi key ada di state sebelum move; tidak ada string dieksekusi |
| **Layout thrash saat drag divider** | pointermove flood | RAF-throttle + clamp fraksi (pola EDT-003) |

Tidak berubah: auth/CSRF/Origin checks, AllowedRoots resolve cwd, traversal/NUL rejection.

## 4. Milestone A — Backend: `--max-sessions` + metrics (`TAB-001`, `TAB-009`)

### A.1 Perilaku Target

1. Default perilaku **identik hari ini**: limit 4, sesi ke-5 → `409 MAX_SESSIONS`.
2. `mux-web --max-sessions 6` (atau env `MUX_WEB_MAX_SESSIONS=6`) → sesi ke-7 ditolak,
   6 pertama sukses. Nilai di-clamp ke 1..=16.
3. `GET /api/v1/metrics` menambah field `max_sessions` (angka efektif setelah clamp).
4. Semua test existing yang mengasumsikan 4 tetap hijau (Default impl = 4).

### A.2 Keputusan Desain

* Flag di `config.rs` (`default_value_t = 4`) + clamp di titik wiring (`main.rs`) lewat
  helper `effective_max_sessions()` — bukan di clap validator, supaya `parse_from` test
  tetap sederhana.
* `SessionConfig.max_sessions: usize` menggantikan pemakaian const di registry; const
  `MAX_SESSIONS` dipertahankan sebagai dokumentasi/default unit-test.
* `MetricsResp` additive field — klien lama aman.

### A.3 Acceptance

- [ ] Registry `new_with(max_sessions=6)` → sesi ke-7 gagal `MaxSessions` (unit, pola `session.rs:404`).
- [ ] Handler default (test-server) → 5th POST `409 MAX_SESSIONS`.
- [ ] `metrics.max_sessions == 4` pada default; `--max-sessions 99` → clamp 16.
- [ ] `cargo test` 100%, clippy/fmt bersih.

## 5. Milestone B — Frontend logic murni (`TAB-002/005/006` model)

Modul baru `web/src/apps/editor/terminalTabsLogic.ts` (DOM-free, node-tested):

```ts
export interface TermTab  { key: string; sessionId: string; label: string; workDir: string|null }
export interface TermGroup{ key: string; tabs: TermTab[]; activeKey: string|null; flex: number }

createTab(groups, {sessionId, workDir}, max?)   // label bash/bash 2…; aktivasi; null jika maxReached
closeTab(groups, tabKey)                        // -> {groups, closedSessionId|null}; kolaps grup kosong
setActive(groups, tabKey)
moveTab(groups, tabKey, toGroupKey, index?)     // reorder/pindah; kolaps grup asal bila kosong
splitToNewGroup(groups, tabKey)                 // grup baru di kanan; flex sumber 50/50
adjustGroupFlex(groups, groupKey, deltaFrac)    // clamp 0.15..0.70 lalu renormalisasi
maxReached(groups, maxSessions) : boolean
nextLabel(groups) : string                      // bash, bash 2, bash 3…
```

Semua operasi immutable (return array baru), key via counter monotonik (tanpa crypto agar deterministik di test).

### Acceptance

- [ ] vitest `terminalTabsLogic.test.ts` ≥16 kasus hijau (RED dulu: modul belum ada).
- [ ] Invariant: total `flex` ≈ 1 (±1e-6) setelah tiap opsi; tidak ada grup tanpa tab;
      `activeKey` selalu menunjuk tab yang ada.

## 6. Milestone C — Wiring `TextEditorView.tsx` (`TAB-001..008`)

### C.1 Perilaku Target (VS Code parity)

1. Header panel: `[tab][tab][tab] …  [＋] [⫿ split] [↻ restart] [✕ hide]` + label cwd aktif
   + chip versi (V051 tetap). Tab aktif highlight; ✕ pada tab menutup sesinya.
2. Body panel: flex-row of groups; tiap grup menampilkan terminal aktifnya full-size;
   pembatas antar-grup draggable (RAF, clamp). Semua instance `TerminalView` mounted —
   hanya yang aktif per-grup visible (CSS), scrollback terjaga (TAB-003).
3. Shortcut: `Ctrl+\`` toggle panel; `Ctrl+Shift+\`` = terminal baru di grup aktif
   (atau split bila sedang fokus split-mode? — diputuskan: selalu terminal baru);
   `Escape` di area terminal tidak menutup panel.
4. Drag & drop: tab `draggable`; drop pada tab lain/grup = move/reorder; drop pada
   body-area grup lain = pindah; grup yang kehabisan tab hilang (flex dinormalisasi).
5. Restart per-tab: `DELETE` + `POST` cwd sama → update `{sessionId, workDir}` in-place.
6. EDT-009 dialog: teks menyebut jumlah terminal yang akan ditutup bila Replace.
7. Tombol `＋` disabled ketika `spawning` atau `maxReached(groups, metrics.max_sessions)`.

### C.2 Keputusan Desain

* State editor: `groups: TermGroup[]`, `panelOpen: boolean` menggantikan
  `termId/showTerminal`. `toggleTerminal()` lama dihapus; `nextTerminalAction` tetap
  dipakai untuk kompatibilitas? — **dihapus pemakaiannya**, digantikan logika grup.
* DnD pakai HTML5 native (`draggable`, `dataTransfer.setData('text/tabkey', …)`);
  fallback touch: tombol split/close tetap membuat fitur tetap usable (catatan §8).
* Label tab = `displayWorkDir(...).label` bila workDir dikonfirmasi, else `bash N`.

### C.3 Acceptance

- [ ] Manual E2E (Termux/Linux): buka 3 terminal → switch scrollback utuh → split
      side-by-side → drag tab antar grup → tutup tengah → grup kolaps → tutup semua →
      panel hilang → `ls /api/v1/terminals` bersih.
- [ ] vitest + build hijau; tidak ada regresi V051 (banner/chip masih tampil).

## 8. Keputusan Desain & Open Questions

1. **Limit configurable, bukan dinaikkan paksa** — default tetap 4 sesuai spec 000 §12;
   pengguna low-end tak terpengaruh, power-user naikkan via flag/env. ✅ dipilih.
2. **Split = terminal BARU** (bukan memindahkan tab) — parity VS Code. ✅
3. **Persist layout tab antar reload** — tunda; sesi PTY pun mati saat server restart,
   persist hanya menyesatkan. Catat sebagai kandidat v0.6.1.
4. **DnD sentuh Android** — HTML5 DnD andal untuk mouse; sentuhan Android Chrome
   mendukung sebagian. Fallback: semua aksi tersedia via tombol. Touch-drag penuh
   ditunda (open question, tidak blokir Green).
