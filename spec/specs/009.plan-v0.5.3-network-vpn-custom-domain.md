## 1. Latar Belakang & Risiko

### 1.1 Skenario User

1. **VPN mesh** (Tailscale/WireGuard/Netbird): HP Termux punya IP tunnel (mis. `100.101.x.x`
   Tailscale CGNAT atau `10.8.0.2` WG). Laptop di mesh yang sama ingin membuka desktop web
   via IP tunnel atau via **MagicDNS** (`pixel.tail-scale.ts.net`).
2. **Network khusus** (LAN kantor/lab dengan DNS internal): user ingin akses via
   `mux.lab.internal` yang resolve ke IP device.
3. **Domain sendiri / reverse proxy nanti**: `mux.example.com` → device (Cloudflare Tunnel,
   frp, nginx). MVP tidak memasang proxy, tapi Host header harus bisa diizinkan.

### 1.2 Kondisi Saat Ini (fakta kode — titik awal)

| Fakta | Lokasi | Catatan |
|---|---|---|
| Bind: default `127.0.0.1`; `--lan` → `0.0.0.0`; `--bind <addr>` eksplisit | `src/config.rs:9-18`, `effective_bind()` `:96-102` | Sudah fleksibel; VPN IP bisa dipakai sebagai `--bind` manual |
| Enumerasi interface untuk banner LAN | `src/main.rs:24-48` `private_ips()` — filter `is_private() && !loopback && !link_local` (v4), `is_unique_local` (v6) | Tailscale `100.64/10` **bukan** `is_private()` (CGNAT) → **tidak tampil** di banner; WG `10.x` tampil |
| Gate Host/Origin | `src/http.rs:292-370` `host_origin_middleware()` — Host ok jika: IP parse & (`is_private()` \|\| `== effective_bind`) **atau** literal `localhost`; selain itu `403 HOST_REJECTED` | Domain apa pun (MagicDNS/internal/public) → **ditolak**; CGNAT `100.64/10` → `is_private()` false → **ditolak** juga saat diakses via IP tunnel Tailscale |
| Origin check non-GET: scheme + host harus = Host header | `src/http.rs:338-367` | Otomatis ikut allowlist (bandingkan dengan Host yang sudah lolos) |
| Auth tetap wajib untuk semua `/api/v1/*` kecuali `pair`/`health`/share publik | `src/http.rs:253-278` | Tidak diubah — perluasan akses tidak melewati pairing |
| TLS opsional (`--tls-cert/--tls-key`, `--generate-cert` self-signed) | `src/config.rs:20-30`, `src/main.rs:97-111` | Sertifikat self-signed hanya SAN `127.0.0.1`+`localhost` (`main.rs:66-69`) → warning browser untuk domain/IP lain |
| Test keamanan Host/Origin existing | `tests/security_tests.rs` | Wajib tetap hijau (regresi nol) |

### 1.3 Risiko Tanpa Desain

- **Workaround berbahaya**: user mem-bypass dengan mengedit kode atau mematikan middleware
  → shell terekspos tanpa gate Host.
- **Kebingungan**: banner hanya mencetak `127.0.0.1` + IP LAN biasa; user VPN tidak tahu
  URL mana yang dipakai; `HOST_REJECTED` tanpa penjelasan.
- **Rebinding**: jika allowlist dibuat terlalu longgar (wildcard `*`, suffix bebas), domain
  publik attacker bisa menyapa server → DNS rebinding. MVP wajib **exact match only**.

## 3. Threat Model

| Skenario | Vektor | Pertahanan Wajib |
|---|---|---|
| **DNS rebinding** | Attacker punya domain `evil.com` → A record `127.0.0.1`; browser korban mengirim Host `evil.com` | Allowlist **exact match**; wildcard/suffix ditolak di MVP (`NET-006`); `evil.com` tidak pernah lolos kecuali user mengetikkannya sendiri |
| **Host spoofing lintas proxy** | Header `X-Forwarded-Host` dipalsukan | MVP **mengabaikan** header forwarded sepenuhnya (tidak dibaca); reverse-proxy trust ditunda (§9) |
| **Akses VPN tanpa pairing** | Tetangga mesh membuka URL | Tidak berubah: semua `/api/v1/*` tetap butuh cookie sesi (`auth_middleware`), pairing single-use + rate-limit tetap |
| **Allowlist injection** | `--allowed-hosts 'a.com,..,b.com'`, `' http://x '`, `''` | Parser ketat (`NET-006`): trim per entri, tolak invalid dengan pesan entri ke-n; fail-fast sebelum bind |
| **CGNAT ambiguity** | `100.64/10` dipakai ISP (bukan VPN) di beberapa negara | Tetap diterima di gate Host hanya bila koneksi memang sampai ke server (L3 sudah membatasi); risiko setara LAN — warning tanpa TLS tetap tampil |
| **Banner info leak** | Mencetak domain internal ke log | Banner hanya ke stdout lokal (bukan API/log terstruktur); tidak ada perubahan aturan "log tanpa secret" |

Yang **tidak** dilindungi 009: kebocoran via plain HTTP di jaringan tidak tepercaya (tetap
dokumentasi: pakai TLS), DoS bandwidth, auth bypass apa pun.

## 4. Milestone A — Host Allowlist & CGNAT (`NET-001`, `NET-002`, `NET-006`)

### 4.1 Perilaku Target

1. `mux-web --allowed-hosts pixel.tail-scale.ts.net,mux.lab.internal` → request dengan
   `Host: pixel.tail-scale.ts.net:7681` (atau tanpa port) → **lolos**; `Host: evil.com`
   → tetap `403 HOST_REJECTED`.
2. Case-insensitive: `PIXEL.TAIL-SCALE.TS.NET` lolos.
3. `Host: 100.101.102.103:7681` (IP Tailscale) lolos **tanpa** flag apa pun (CGNAT masuk
   kelas private gate) — memperbaiki gejala "VPN tidak bisa akses via IP".
4. Tanpa flag: perilaku persis hari ini (regresi `security_tests.rs` nol).
5. Parser: entri di-trim; `''`, `*`, `*.ts.net`, `http://x`, `x/y`, spasi internal → error
   startup `invalid --allowed-hosts entry #N: '…'` dan exit 1.

### 4.2 Keputusan Desain

* Config baru `allowed_hosts: Vec<String>` di `Config` (flag koma-separated, env
  `MUX_WEB_ALLOWED_HOSTS`) + normalisasi ke lowercase saat parse; helper
  `Config::effective_allowed_hosts()` melakukan validasi `NET-006` dan fail-fast di `main`.
* Gate: `host_ok` diperluas — setelah cek IP/localhost existing, cek
  `effective_allowed_hosts().contains(&host_part.to_ascii_lowercase())`.
* CGNAT: tambah helper `is_gate_ok_ip()` (di `http.rs` atau `config.rs`) yang menerima
  `is_private() || cgnat(100.64/10) || == effective_bind`; dipakai gate **dan**
  `private_ips()` banner (`main.rs:24`) agar konsisten. CGNAT check: `v4.octets()[0]==100 && (v4.octets()[1] & 0xC0) == 64`.
* Port tetap divalidasi seperti sekarang (kosong atau == `config.port`).

### 4.3 Acceptance Milestone A

- [ ] Unit parser: daftar valid/invalid sesuai §4.1.5 (tabel kasus di test).
- [ ] `security_tests.rs` baru: `Host: allowed.example` → 200/404 (bukan 403);
      `Host: evil.com` → 403; `Host: 100.64.1.2` → lolos; tanpa flag `100.64.1.2` → 403 (regresi).
- [ ] `cargo test` 100% • clippy 0 • fmt 0.

## 5. Milestone B — Advertise & Banner (`NET-003`, `NET-004`, `NET-005`)

### 5.1 Perilaku Target

1. `mux-web --lan --advertise-addr pixel.tail-scale.ts.net:7681` → banner mencetak
   `VPN/Custom: https://pixel.tail-scale.ts.net:7681/<bootstrap>` (scheme sesuai TLS)
   **sekaligus** IP LAN biasa.
2. `--advertise-addr` tanpa `--allowed-hosts`: entri otomatis masuk allowlist (satu sumber
   kebenaran; user tidak mengulang dua kali). Sebaliknya tidak otomatis.
3. Banner `LAN access:` kini memuat juga CGNAT IP (Tailscale) yang terdeteksi di interface.
4. `HOST_REJECTED` body: `{"error":{"code":"HOST_REJECTED","message":"invalid Host header — add it via --allowed-hosts"}}` (pesan generik, tanpa echo nilai Host).

### 5.2 Keputusan Desain

* `advertise_addrs: Vec<String>` (flag koma-separated, env `MUX_WEB_ADVERTISE_ADDRS`);
  validasi ringan (host[:port], host boleh domain/IP); saat membangun allowlist efektif:
  `allowed_hosts ∪ advertise_addrs(host-part)`.
* Banner: refactor cetak URL ke helper `print_access_urls(scheme, port, bootstrap, ips, advertises)`
  agar testable; urutan: loopback → advertise → private/CGNAT per interface.
* Tidak ada perubahan binding/socket sama sekali.

### 5.3 Acceptance Milestone B

- [ ] Unit `print_access_urls` (capture via trait/writer atau refactor ke fungsi murni
      penghasil `Vec<String>`): memuat loopback, advertise, CGNAT; tanpa duplikat.
- [ ] Integrasi: `--advertise-addr a.test` lalu request `Host: a.test` → lolos (bukan 403).
- [ ] Manual smoke Termux: Tailscale on → banner menampilkan IP `100.x` + URL MagicDNS.
