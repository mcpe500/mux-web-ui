# Mux Web UI — v0.2.1 Implementation Checklist & Verification Matrix

Status: in progress (started)  
Companion to: [`002.plan-v0.2.1.md`](./002.plan-v0.2.1.md)  
Rule: Every task requires TDD Red -> Green -> Refactor execution. A milestone is
not done because the installer "looks" like it works; the CI `installer-test`
scenarios must pass.

---

## TDD Execution Loop Standard

For every item:
1. **Red**: Write a failing scenario for the item before production code
   (skenario di job CI `installer-test` atau smoke lokal).
2. **Green**: Write minimal code to pass the scenario.
3. **Refactor**: Clean up while keeping scenarios green.
4. **Verify**: Run full test suite (`cargo test`) + budget check.

## Langkah 1 — Milestone A: Release pipeline multi-target

- [ ] **A.1** Job `release` di `.github/workflows/ci.yml` diubah ke matrix
      4 target: `x86_64-unknown-linux-gnu` (native), `x86_64-unknown-linux-musl`
      (rustup target + musl), `aarch64-unknown-linux-gnu` (gcc-aarch64-linux-gnu),
      `aarch64-linux-android` (NDK r27 + cargo-ndk, API 24)
- [ ] **A.2** Packaging per target: `mux-web-<ver>-<target>` + `.sha256` +
      `checksums.txt` agregat di `dist/` (DIST-001..005)
- [ ] **A.3** Upload GitHub Release (softprops/action-gh-release) berisi
      seluruh artifact (DIST-006)
- [ ] **A.4** Smoke: binary x86_64 → `mux-web --version` = `0.2.1`; target
      lain → `file`/`readelf` arsitektur benar; budget check hijau
- [ ] **A.5** Tag percobaan `v0.2.1-rc.1` → artifact ter-upload di Release

## Langkah 2 — Milestone B: `install.sh` binary-first

- [ ] **B.1** Red: skenario installer-test gagal (install.sh masih clone +
      compile)
- [ ] **B.2** Detect platform: Termux (`TERMUX_VERSION`) vs Linux; `uname -m`
      → mapping target (DIST-007)
- [ ] **B.3** Versi: `--version <ver>` / `MUX_WEB_VERSION` → pin;
      tanpa argumen → GitHub API `releases/latest` (DIST-008)
- [ ] **B.4** Download binary + `.sha256` dari base URL; verifikasi
      `sha256sum -c`; mismatch → batalkan tanpa install (DIST-009)
- [ ] **B.5** Backup binary lama → `mux-web.old`; install baru ke `$INSTALL_DIR`
      + `chmod +x`; smoke `--version`
- [ ] **B.6** Fallback source: download/verify gagal → warning + compile
      bila `cargo` ada; `pkg install rust git` hanya pada jalur fallback
      (DIST-010)
- [ ] **B.7** `MUX_WEB_INSTALL_DIR` override direktori

## Langkah 3 — Milestone B: `update.sh` binary-first

- [ ] **C.1** Red: skenario update gagal (masih git pull/rebuild)
- [ ] **C.2** Deteksi versi terpasang via `mux-web --version`; query latest;
      sama → "sudah terbaru" (DIST-011)
- [ ] **C.3** Download + verify SHA-256; backup → `mux-web.bak`; install baru
- [ ] **C.4** Smoke `mux-web --version` pasca-install; gagal → pulihkan
      `.bak`, exit non-zero (DIST-012)
- [ ] **C.5** `update.sh --rollback` manual idempotent; notice pairing
      breaking-change v0.2 tetap dicetak

## Langkah 4 — CI `installer-test` (DIST-013)

- [ ] **D.1** Job `installer-test` (ubuntu-latest): build release x86_64,
      staging `dist/` (binary + `.sha256` + `checksums.txt`)
- [ ] **D.2** Skenario 1: `MUX_WEB_BASE_URL=file://...` install bersih →
      binary terpasang, `--version` benar
- [ ] **D.3** Skenario 2: `install.sh --version 0.2.0` (pin) → versi sesuai
- [ ] **D.4** Skenario 3: `.sha256` rusak → install ditolak, exit non-zero,
      binary lama utuh
- [ ] **D.5** Skenario 4: `update.sh` dua versi staging → upgrade sukses;
      smoke gagal (inject) → `.bak` dipulihkan
