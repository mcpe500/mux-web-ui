# Mux Web UI — v0.2.1 plan: Distribution (prebuilt binary + installer tanpa Rust)

Status: approved  
Target: Linux x86_64/ARM64 dan Termux/Android ARM64  
Brand: Distribution — "I shipped it, then I made it installable."

Dokumen ini dikerjakan dengan test-driven development mengikuti
[`000a.plan-test.md`](./000a.plan-test.md) dan diperiksa dengan checklist
mengikuti pola [`001b.plan-checklist.md`](./001b.plan-checklist.md). Checklist
pelaksanaan v0.2.1 dicatat di `002b.plan-checklist.md`.

## 1. Latar belakang dan risiko

v0.2 (lihat [`001.plan-v0.2.md`](./001.plan-v0.2.md) dan
`001b.plan-checklist.md`) menghasilkan fitur lengkap: auth + TLS, session
persistence, test suite + CI. Namun **proses distribusi masih developer-grade**:
pengguna wajib menginstal Rust dan meng-compile sendiri dari `main`.

### 1.1 Fakta kode v0.2 yang menjadi titik awal

- `Cargo.toml:3` — versi `0.2.0`; `config.rs:6` —
  `#[command(author, version, about)]` → `mux-web --version` **sudah berfungsi**
  (clap auto, membaca `CARGO_PKG_VERSION`), sehingga updater dapat membandingkan
  versi tanpa perubahan binary.
- `.github/workflows/ci.yml:72-98` — job `release` hanya build
  `linux-x86_64` native + `checksums.txt`, lalu upload via
  `softprops/action-gh-release@v2`. Tidak ada binary ARM64/Termux/musl.
- `ci.yml:38-52` — target `aarch64-linux-android` hanya `cargo check`
  (cross-check), bukan build binary rilis.
- `install.sh:53-62` — fetch `main` via git clone (atau tarball) lalu
  `cargo build --release`; `install.sh:29-43` — pada Termux fresh environment
  auto-install `rust git tar` (`pkg install`). **1-liner installer butuh
  toolchain lengkap.**
- `update.sh:38-55` — `git pull origin main` + rebuild, atau clone + rebuild.
  Update selalu dari `main` (bukan tag): tidak reproducible antar waktu.
- `git tag` kosong — **belum ada GitHub Release/tag sama sekali**, padahal
  `001b.plan-checklist.md:3` mengklaim "v0.2 ready & released". Klaim ini
  keliru; rilis nyata baru dibuat di v0.2.1.
- `install.sh:49-51` — dukungan "local prebuilt" sudah ada (copy
  `target/release/mux-web` bila berada di dalam repo), bisa dijadikan dasar.
- `tests/traceability.md` sudah ada (baris AUTH/SESS/FS/TERM/LIFE/CI/SEC);
  family DIST belum terdaftar.

### 1.2 Scope v0.2.1

1. **Release pipeline multi-target** — build binary untuk 4 target, checksum,
   GitHub Release otomatis pada tag `v0.2.1`.
2. **Installer binary-first** — `install.sh` mendownload binary rilis,
   memverifikasi SHA-256, install **tanpa Rust**; compile-from-source menjadi
   fallback eksplisit.
3. **Updater + rollback** — `update.sh` binary-first, banding versi, backup +
   auto-rollback bila gagal; tidak pernah install dari `main`.
4. **Testability** — env `MUX_WEB_BASE_URL` agar installer dapat diuji di CI
   tanpa release sungguhan.
5. **Dokumentasi** — README dibedakan: install dari release vs build dari
   source; traceability +DIST-001..014.

## 3. Threat model (supply chain)

Rilis binary memperkenalkan vektor baru: binary yang di-download pengguna bisa
berbeda dari yang di-build di CI.

| Attacker | Akses | Dilindungi oleh |
|---|---|---|
| MITM pada download (network) | Suntik binary jahat | Download wajib via HTTPS (github.com); verifikasi SHA-256 dari asset `.sha256` yang di-download terpisah dari binary (`DIST-005`, `DIST-009`) |
| Repo/CI dikompromi | Binary hasil build diganti | Checksum dihitung dari artifact build CI yang sama dalam satu job; release hanya dari tag `v*` (bukan `main`), `DIST-006` |
| Pengguna install versi lama bermasalah | Binary lama/buggy | `install.sh --version` pin; `update.sh` compare versi; rollback `.bak` (`DIST-008`, `DIST-012`) |
| Phishing "update" | User menjalankan script jahat | Di luar model: script diambil dari repo resmi; update hanya via `update.sh` resmi |

Batasan yang dicatat: GitHub Release API dan asset host di luar kontrol project
(availability); verifikasi checksum tidak menandatangani binary (signing
dengan key pihak ketiga = di luar scope v0.2.1, lihat bagian 9).

## 4. Milestone A — Release pipeline multi-target

### A.1 Target matrix

Job `release` diubah menjadi matrix 4 target:

| Target | Arch/OS | Alat build |
|---|---|---|
| `x86_64-unknown-linux-gnu` | Linux x86_64 (glibc) | runner native `ubuntu-latest` |
| `x86_64-unknown-linux-musl` | Linux x86_64 (static) | rustup target + musl toolchain dari rustup component |
| `aarch64-unknown-linux-gnu` | Linux ARM64 (glibc) | rustup target + `gcc-aarch64-linux-gnu` (cross) |
| `aarch64-linux-android` | Termux/Android ARM64 | rustup target + **NDK r27 + cargo-ndk**, API 24 (`cargo-ndk -t arm64-v8a -p 24`) |

Catatan `nix` crate: mendukung `target_os = "android"` dan musl; `ring`/`rcgen`
membutuhkan C cross-compiler (tersedia via apt). Build release memakai
`[profile.release]` yang sudah ada (`Cargo.toml:8-12`: LTO, strip).

### A.2 Packaging & checksum

Per target, artifact:
- `mux-web-<ver>-<target>` (binary mentah, nama konsisten — dipakai installer)
- `mux-web-<ver>-<target>.sha256` (checksum satu file)
- `checksums.txt` (agregat seluruh binary + sha256, format `sha256sum`)

Staging: `dist/` lalu upload ke GitHub Release (softprops/action-gh-release
tetap dipakai, `DIST-006`).

### A.3 Acceptance criteria Milestone A

- Push tag `v0.2.1` → 4 binary + 4 `.sha256` + `checksums.txt` ter-upload.
- Setiap binary lolos smoke test: `mux-web --version` menampilkan versi
  `0.2.1` (uji x86_64 di runner; aarch64/arm64 & android diverifikasi via
  `file`/`readelf` + smoke saat device tersedia).
- Ukuran tetap dalam budget (hard limit ≤ 50 MiB compressed, PERF-001).
- `DIST-001..006` lulus.

## 5. Milestone B — Installer & updater binary-first

### B.1 Flow `install.sh` (DIST-007..010)

1. **Detect platform**: Termux (`TERMUX_VERSION` / path `com.termux`) vs Linux;
   `uname -m` → arch. Mapping: Termux+aarch64 → `aarch64-linux-android`;
   Linux aarch64 → `aarch64-unknown-linux-gnu`; Linux x86_64 →
   `x86_64-unknown-linux-gnu` (musl binary tersedia manual; auto-detect libc
   di luar scope).
2. **Tentukan versi**: `--version <ver>` / env `MUX_WEB_VERSION` → versi
   spesifik; tanpa argumen → query GitHub API `releases/latest`
   (`DIST-008`).
3. **Download** dari base URL (default `https://github.com/mcpe500/
   mux-web-ui/releases/download`): binary + `.sha256`; HTTPS wajib.
4. **Verifikasi**: `sha256sum -c`; mismatch → batalkan, jangan install
   (`DIST-009`).
5. **Backup**: bila `mux-web` lama ada → `mv` ke `mux-web.old` sebelum
   mengganti.
6. **Install**: `install` ke `$INSTALL_DIR` (logika deteksi direktori dari
   v0.2 dipertahankan: Termux → `/data/data/com.termux/files/usr/bin`,
   `/usr/local/bin`, `$HOME/.local/bin`), `chmod +x`.
7. **Fallback source**: bila download/verify gagal (offline, arch tidak
   didukung) → cetak warning eksplisit + compile-from-source bila `cargo`
   tersedia (`DIST-010`); bila tidak, exit dengan pesan yang jelas.
8. Smoke: `mux-web --version` setelah install.

Termux fresh-environment: `pkg install rust git` **tidak lagi dilakukan** pada
jalur binary; hanya dipicu pada fallback source.

### B.2 Flow `update.sh` (DIST-011..012)

1. Deteksi binary terpasang + versi sekarang: `mux-web --version` (parse).
2. Query versi terbaru (API `releases/latest`).
3. Sama → "sudah terbaru", exit 0.
4. Lebih baru → download binary + `.sha256` (base URL sama dengan install),
   verifikasi SHA-256.
5. **Backup**: `mux-web` → `mux-web.bak`; install binary baru.
6. **Smoke + rollback**: jalankan `mux-web --version` (timeout pendek); gagal
   → pulihkan `mux-web.bak`, exit non-zero dengan pesan (`DIST-012`).
7. `update.sh --rollback` manual: pulihkan dari `.bak` (idempotent).
8. **Tidak ada git clone/pull dari `main`** pada jalur normal; notice pairing
   breaking-change v0.2 tetap dicetak setelah update.

### B.3 Testability (DIST-013)

- `MUX_WEB_BASE_URL` menggantikan base URL download (mendukung `https://` dan
  `file://` untuk staging lokal) — installer/updater dapat diuji penuh di CI
  tanpa release sungguhan.
- CI job `installer-test` (ubuntu-latest): build release x86_64 di job,
  susun `dist/` staging (binary + `.sha256` + `checksums.txt`), lalu jalankan:
  1. `install.sh` (via `MUX_WEB_BASE_URL=file://...`) → binary terpasang,
     `--version` benar;
  2. `install.sh --version 0.2.0` (pin) → versi sesuai;
  3. checksum rusak (tulis `.sha256` salah) → install ditolak, exit non-zero,
     binary lama utuh;
  4. `update.sh` dengan staging dua versi → upgrade berhasil; simulasi smoke
     gagal (inject) → `.bak` dipulihkan.
- Uji Termux nyata: manual di device (termasuk fallback source) — dicatat di
  checklist.

### B.4 Acceptance criteria Milestone B

- Instalasi bersih di Linux x86_64 **tanpa Rust** berhasil dari staging
  (CI) — `DIST-007` lulus.
- Pin versi, penolakan checksum, dan rollback teruji di CI (`DIST-008/009/012`).
- Jalur fallback source tidak pernah dijalankan pada skenario normal.
- `DIST-007..014` lulus (DIST-014 = README).

## 7. Keputusan desain dan open questions

Keputusan (ditetapkan v0.2.1):
- Binary mentah per target (bukan tarball) — sederhana, nama stabil untuk
  installer; gzip-ability sudah diukur `check_budget.sh`.
- Release hanya dari tag; `main` tidak pernah menjadi sumber install/update.
- Checksum di-download terpisah dari binary (MITM harus merusak dua asset).
- Backup `.old`/`.bak` disimpan di direktori install (bukan data dir).
- `--version` produk sudah ada; tidak ada perubahan binary untuk v0.2.1
  (murni proses distribusi).

Open questions (diputuskan saat implementasi, dicatat di checklist 002b):
- Auto-detect glibc vs musl di Linux — rekomendasi: skip, dokumentasikan.
- Signing binary (cosign/GPG) — rekomendasi: tunda, bukan scope v0.2.1.
- Caching musl/NDK di CI (`Swatinem/rust-cache` per target sudah ada) —
  ukur waktu build sebelum optimasi.

## 8. Bukan scope v0.2.1

- Signing kriptografis artifact (cosign/GPG) dan TUF/update framework.
- Auto-update di dalam produk (`mux-web self-update`); tetap via script.
- Target baru selain 4 di atas (darwin, windows, armv7, x86 android).
- Auto-detect libc (musl detection), multi-distro packaging (deb/rpm).
- Perubahan fitur produk; v0.2.1 murni distribusi + dokumentasi.
